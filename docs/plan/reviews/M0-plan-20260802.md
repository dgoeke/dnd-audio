## Verdict

Changes requested. The plan is well scoped overall, but I would not approve implementation until the two invariant-level blockers are resolved.

## Findings

### P0 — The network fixture violates INV-05/INV-06

The plan explicitly exempts `host_smoke` tests and blocks only outbound `connect` calls ([working plan](docs/plan/milestones/M0-foundation.md:156)). That leaves several holes:

- Unconnected UDP `sendto`, DNS resolution, and network activity in subprocesses remain possible.
- The proposed exemption permits any `host_smoke` test to use the network, while INV-06 says `models fetch` is the only network-permitted command ([INV-06](docs/plan/INVARIANTS.md:50)).
- The test allegedly proving the exemption is itself excluded by the gate, so it proves nothing during M0 verification ([proof table](docs/plan/milestones/M0-foundation.md:181)).

Do not exempt `host_smoke`; real Qwen smoke tests should use already-fetched models offline. Block AF_INET/AF_INET6 operations while allowing AF_UNIX, including DNS and UDP. If tests spawn network-capable subprocesses, use OS-level network isolation where available or explicitly document and test that remaining boundary.

### P0 — The report plan does not satisfy INV-13, and INV-13 is partly impossible

The planned report tests cover rollup, schema validation, one provenance heuristic, and atomic replacement ([proof](docs/plan/milestones/M0-foundation.md:180)). They do not prove:

- A status for every stage, including `skipped`.
- Structured errors.
- Hashes of every produced deliverable.
- A deterministic `decisions` section.
- Stable provenance when stage completion order changes.

All are required by [INV-13](docs/plan/INVARIANTS.md:105) and the [spec’s report contract](dnd-audio-ingestion-agent-spec.md:773).

The spec/invariant is also literally wrong as written: `ingest-report.json` is itself a deliverable, so it cannot contain the SHA-256 of its own final bytes without changing those bytes. Amend the spec and INV-13 to require hashes of every other produced deliverable, or define an external report-hash sidecar.

### High — Determinism is tested only in the easiest execution order

Canonical JSON key sorting does not sort arrays or neutralize insertion/completion order. A report “stage accumulator” can therefore emit different stage or decision ordering depending on whether transcription or mixing finishes first. The current single-order rollup test would pass.

Require:

- Stage records keyed by a fixed stage enum or explicitly sorted.
- A test applying identical stage updates in opposite orders and comparing deterministic projections.
- Schema generation in fresh processes with different `PYTHONHASHSEED` values, not only repeated writes in one process.

That is the behavior INV-02 actually requires ([INV-02](docs/plan/INVARIANTS.md:22)).

### High — The new hashing and model interfaces lack a bounded-memory contract

The plan adds generic SHA-256 helpers and a fake that hashes audio content ([steps 2 and 7](docs/plan/milestones/M0-foundation.md:130)), but no listed proof exercises hashing. An implementation based on `Path.read_bytes()` or `waveform.tobytes()` would pass every planned test while loading a multi-gigabyte recording into memory, violating [INV-07](docs/plan/INVARIANTS.md:60).

Either defer file hashing to M1 or require a streaming `sha256_file()` with a bounded chunk size and a test that rejects unbounded reads. Protocol request types should likewise carry bounded windows and integer sample coordinates; they should not accept an unconstrained full-session array.

### High — The checked-in skeleton schemas have no evolution policy

The plan checks in a small M0 manifest schema, then says M1 will “replace” it ([manifest plan](docs/plan/milestones/M0-foundation.md:139), [non-goal](docs/plan/milestones/M0-foundation.md:214)). Adding M1’s required fields under the same `schema_version` would silently redefine version 1, contrary to the spec’s versioned-schema requirement ([schema contract](dnd-audio-ingestion-agent-spec.md:727)).

Declare the M0 manifest/report skeleton versions provisional and require an explicit version bump at the owning milestone, or define their stable envelope now and only add version-compatible optional content later.

### Medium — “Full session.yaml shape” is not actually proved

The proposed fixture and rejection table ([proof](docs/plan/milestones/M0-foundation.md:175)) omit several explicit requirements:

- Optional model and aligner revisions ([spec](dnd-audio-ingestion-agent-spec.md:629)).
- Rejection of `max_segment_s > 120` under the current adapter assumption ([spec](dnd-audio-ingestion-agent-spec.md:584)).
- A recovery override containing neither timing value; the plan tests only the “both supplied” case ([override contract](dnd-audio-ingestion-agent-spec.md:394)).
- The configurable thresholds later required by activity and automix.

Enumerate every field, default, range, and cross-field rule in the proof table. The 120-second default/limit depends on OQ-009 and must cite `OQ-009` in the relevant code or test, per [OPEN-QUESTIONS.md](docs/plan/OPEN-QUESTIONS.md:3).

### Medium — The CLI proof can pass without a usable CLI

Direct `Typer` `CliRunner` tests can pass even if `[project.scripts]`, the build backend, or `src/` package discovery is wrong. The user contract is specifically `uv run dnd-audio ...` ([spec](dnd-audio-ingestion-agent-spec.md:190)).

Add an offline integration check such as `uv run --no-sync dnd-audio --help` and representative subcommand invocations.

The charter is also internally contradictory: it lists `doctor` among commands wired to not-implemented stubs, then requires `doctor` to genuinely work ([charter](docs/plan/milestones/M0-foundation.md:34)). The proof table repeats that contradiction by saying every command exits as unimplemented immediately before the real-doctor test. Amend the charter now: processing/setup commands except `doctor` are stubs; `doctor` is implemented.

### Medium — Several proof rows overclaim what their commands establish

- `uv lock --check` does not prove `.python-version` contents, the exact `requires-python` interval, the license, or that files are committed ([proof](docs/plan/milestones/M0-foundation.md:169)).
- Running the gate inside an already activated shell does not prove `.envrc` activates that shell. Verification needs a clean `direnv exec .` invocation.
- The plan identifies “default sync contains no Torch” as a known risk but provides no gate assertion for it ([risk](docs/plan/milestones/M0-foundation.md:77)).
- `.gitignore` coverage is only “reviewed,” not tested.

Use `tomllib` assertions for project metadata, `git ls-files` during verification, `direnv exec .` for activation, dependency-graph inspection for the no-Torch rule, and `git check-ignore --no-index` with representative sentinel paths.

### Medium — Cache identity has no canonical resolved-configuration boundary

The plan creates config models and hashing separately but never specifies what bytes constitute the resolved configuration. Later stages may hash raw YAML, making omitted defaults differ from explicitly written defaults, or may omit newly added output-affecting fields. That undermines [INV-08](docs/plan/INVARIANTS.md:68).

Define one canonical validated-config projection now: defaults materialized, relative paths normalized without host-specific absolute paths, unknown fields forbidden, and schema/implementation version included. Test that omitted versus explicit defaults hash identically and that every output-affecting change changes the hash.

## Over-building

The content-hash-generated fake transcript and fake word timings are unnecessary M0 complexity. M4 needs a scriptable fake capable of deliberately returning overlap, truncation, alignment failure, and duplicate-text cases. A clever hash-generated fake will likely be replaced.

Likewise, rational-to-public-millisecond conversion is not consumed until M4. Either defer it, or define it now as an integer-millisecond quantizer with an explicit tie-rounding rule and boundary tests; do not expose a general float-returning helper that later code may use internally.

The flake, schema-drift rail, doctor, canonical JSON, and protocol scaffolding are not over-building; they are legitimate M0 gate items.

## Recommended revision order

1. Amend the impossible report-hash language and the `doctor` contradictions.
2. Redesign the network block with no `host_smoke` exemption.
3. Define versioned report/schema envelopes and deterministic stage ordering.
4. Make hashing and protocol inputs explicitly bounded and sample-exact.
5. Enumerate and test the complete configuration contract and resolved-config hash.
6. Replace the semantic fake with a small scripted fake.
7. Strengthen the executable gate proofs.

No new unregistered DJI timing assumption appears in this plan. The existing OQ-008/OQ-009-dependent code paths still need explicit `OQ-` citations when implemented. No files were modified.
