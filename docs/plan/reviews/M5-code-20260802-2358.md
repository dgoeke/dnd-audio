# M5 code review — distilled findings

**Mode:** `code` · **Reviewers:** Codex CLI (`scripts/codex-review.sh code 5`), plus a
fresh-context reviewer agent given the charter, the invariants, and the diff range
`4a471a9..HEAD`. Raw transcripts are gitignored; this is the distillation.

Codex opened with "I would not close M5 in its current state." It was right. Seven of its
findings and one of the second reviewer's were accepted and fixed; the verify phase found four
more of its own. Nothing was rejected outright.

The two reviewers disagreed about the INV-09 prose test, and the disagreement was the most
valuable thing in the review — see finding 3.

---

## Accepted and fixed

### 1. The decoded-loudness check was waived without a decision recording it

`_failures` skipped the loudness comparison whenever `_initial_gain` had declined to aim at the
target, and the true-peak-ceiling case — the one the canonical fixture actually reaches — was
recorded only in a docstring. ADR-0023 documented two guards and the code had three. The gate
criterion and the spec's acceptance criterion 8 both say the stage fails rather than claims
compliance.

Codex's framing was the useful part: *"'Ceiling wins with a warning' is defensible product
behavior, but then the spec and charter must be amended alongside the ADR. The implementation
cannot silently waive their current contract."* That is AGENTS.md's rule about the spec, arrived
at independently.

**Fixed** by amending all three in one commit — the spec's milestone-5 section and criterion 8,
ADR-0023's guard list, and the charter's gate — and by making the report honest: `mix_encoded`
now names *which* tolerances were checked and carries `loudness_normalized`, rather than saying
"within every configured tolerance" about a comparison nothing performed.

### 2. A measurement nobody took counted as a pass

Both compliance checks skipped themselves when their number was `None`. A decode that reported
`-inf` loudness on a run aiming at the target, or a summary with no true-peak line at all,
produced zero failures.

`-inf` and "no line" needed telling apart first: FFmpeg 8.0 prints `Peak: -inf dBFS` for digital
silence, which is a real measurement infinitely below any ceiling, while an absent line means
`peak=true` did not take effect. `Measurement.true_peak_reported` is that distinction; the
second is a new `true_peak_unmeasured` failure.

### 3. The INV-09 prose test could not fail

`test_rewriting_the_graphs_prose_does_not_change_a_single_sample` rewrote
`ActivityDecision.detail` and `ActivityNote.message` in `work/activity.json` and then called
`run_mix` — which rebuilds that document from the attribution cache before mixing. The edit was
overwritten and the mixer never saw it.

The second reviewer read the same test and reported all three INV-09 proofs as real. Codex
traced the write in `run_mix` and did not. A direct check settled it: after the second run, none
of the rewritten strings survive.

**Fixed** by rewriting the prose on the `ActivityGraph` the renderer is *handed* and rendering
twice to different destinations, so no cache can stand in for either. Mutation-checked: a mixer
that folds `len(decision.detail)` into a candidate's weight now fails the test.

### 4. The overlap criterion was a property of the fixture, not of the rule

Codex did the arithmetic: one speaker at score 1000, one at score 0, four inactive tracks, and
the quieter speaker cut by the permitted 6 dB gives

    0.5 / (1 + 0.5 + 4×0.005) × 10^(−6/20) = −15.66 dB

against a shipped `overlap_min_gain_db` of −15. The tests exercised asymmetric scores without an
adverse correction, and an adverse correction only with equal scores — never the cross-product.
The solo margin had an achievability validator from the start; this one had an estimate in a
docstring.

**Fixed** with the twin validator. `EnvelopeConfig.guaranteed_overlap_gain_db(track_count)`
computes the bound and `SessionConfig` refuses a promise it cannot keep — on `SessionConfig`
rather than beside the other one, because the guarantee depends on how many tracks the gain is
divided between. The default moves to −16.0, derived rather than estimated, and OQ-019 records
why the old number was 0.66 dB optimistic. Mutation-checked: restoring −15.0 refuses every
session fixture in the suite.

### 5. Cache state in a subsection INV-02 requires to be stable

The `mix_intermediate` decision said "rendered" or "reused from cache" and carried
`from_cache`, so two runs over an unchanged session disagreed about a session neither had
changed. `record_cache` already carries hits and misses as telemetry.

**Fixed**: the decision describes the intermediate and nothing about how it was obtained. A new
test compares the whole decisions subsection cold against warm.

### 6. The INV-07 composed-path proof did not watch the audio

`TestTheMixPathStreams` instrumented envelope production and `WavWriter.write` but not
`TrackReader.read`. A renderer that collected all six waveforms first and only then interleaved
lazy envelope chunks with writes would have passed.

This is the same hole one level down: M5's *plan* review found the first draft proved only the
audio path, so the envelope was added; the code review found the second draft had stopped
proving the audio path. **Fixed** — both are in one ordered log, and the write has to beat the
last event of each.

### 7. A failed encode lost every measurement it took

`encode_deliverable` recorded the source measurement, the commands, and the attempts only after
`encode_mp3` returned. An exhausted retry budget raises, so the report kept one error string —
and "retain all measurements in the report" is about the failing run above all. The existing
test checked the *exception text*, not the report.

**Fixed**: `EncodeError` carries its attempts and commands, the runner records them before
re-raising, and a new end-to-end test drives the real retry loop with an always-overshooting
decode and asserts four attempts and four encode commands reach the report.

### 8. `process` overwrote each branch's own diagnosis (second reviewer)

ADR-0024 says the final verification's error "does not replace whichever error the branch
already reported". `_failed` stamped the outer exception over every stage neither branch had
recorded, so a mix that fully succeeded was reported `MIX: failed` with a tampering message, and
a genuine ASR crash concurrent with unrelated tampering lost its real diagnostic.

The same reviewer noticed the related gap: `test_a_source_corrupted_after_the_mix_commit_fails_the_run`
corrupts a source from inside `perform_transcript`, which that branch's *own* `verify_unchanged`
then catches — so the test passes with the final check deleted.

**Fixed** both: `_failed` prefers `state.mix_error` / `state.transcript_error` per stage, and a
new test corrupts a source after both branches have verified and committed, where the outer
check is the only thing left that can see it.

## Found by the verify phase itself

### 9. One clamp, spelled two ways

`levels` clamps the level correction to `round(db × 100)` millibels; `EnvelopeStream` built its
bound from `10 ** (db / 20)`. For any clamp whose hundredths round *up* — `round(0.015 × 100)`
is 2 — a track's own permitted correction exceeded the bound the runtime checker enforces, and
an ordinary two-speaker session failed the mix stage with an invariant violation. Reproduced
before fixing. One rounding now, in the unit the graph already speaks.

### 10. The envelope depended on how the caller partitioned it

`_targets` stopped scanning a track at the first span running past the chunk end, so a second
overlapping span was skipped in that chunk and applied in the next. With two overlapping
candidates on one track the envelope differed between `chunk_frames=1000` and the whole session
— and the mix's cache identity carries no window size. M3's merge keeps a track's retained
candidates disjoint, so it is unreachable through the pipeline, which is exactly the reason to
make the bound structural instead of resting on a promise the artifact does not make.
`test_the_same_envelope_comes_out_however_it_is_partitioned` used a single-span graph and could
not see it.

### 11. Charter proof-table names had drifted

Five rows named tests that do not exist under those names (`TestLoudness`, `TestTheMp3`,
`TestBoundedGainShare`, `TestBoundedMixMemory`, `test_the_attack_ramp_fits_inside_the_vad_pad`).
Every proof exists; the names did not. Codex reasonably read the loudness row as a missing proof.
The table now names what is there. One row was worse than a rename: it claimed
`TestGenuineOverlap` covers `mutual_bleed_session`, and no test used that fixture.

### 12. `_peak_of` documented itself wrongly

Its docstring said the first encode's gain is aimed with the number it returns. The gain is
aimed with the true peak `measure` reads off the decode, which accounts for inter-sample overs
and a sample peak does not.

## Deferred, with reasons

- **The INV-09 import test would miss a lazy import inside a function** (Codex). The transitive
  closure of a module import is what it checks, and this package uses a function-level import
  itself (`_peak_of`), so the hole is real. Left as it is: catching it needs either an AST walk
  or an import hook armed during a live `perform_mix`, and the byte-identity and prose proofs
  beside it cover the consequence rather than the mechanism. Recorded in the closeout.
- **`_peak_of` decodes the whole cached intermediate on every warm run** for one report field.
  Bounded and correct, but it is the one place a cache hit still costs a full read. Left until
  a real session says whether it matters.
- **A true-peak retry can fail on loudness instead of resolving.** The retry reduces the gain by
  exactly the overshoot, so on a run that *was* aiming at the target an overshoot above
  `loudness_tolerance_lu` lands outside it. Added as OQ-020's third assumption; no evidence
  either way until a real encode.

## Rejected

None. Every finding either held up under a direct check or was already true of the code.
