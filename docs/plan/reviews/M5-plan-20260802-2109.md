# M5 plan review — Codex, 2026-08-02

Independent critique of the working plan in `../milestones/M5-automix.md`, run before any
code existed (`./scripts/codex-review.sh plan 5`). Distilled from the raw transcript, which
is gitignored because a reviewer quotes every file it read.

**Verdict:** *"I would not implement this plan unchanged. The overall decomposition is good,
but several proposed proofs do not establish the completion gate, and three invariants are
under-specified."*

Twelve findings. **Eleven accepted**, one accepted while its severity was disputed, one
rejected in framing but accepted in substance. The findings changed three defaults, removed
one artifact, split one cache identity, and rewrote five of the thirteen proofs.

---

## Accepted

### 1. Critical — the level correction escapes the gain bound the plan asserts

The plan normalized the *share* so `Σ g = 1`, then applied the per-track voice-level
correction to the audio. The coefficient that actually reaches a sample is `g_t · c_t`, and
`Σ (g·c)` is not bounded by `Σ g = 1`. Six `+6 dB` corrections make a perfectly correlated
mix sum to 2.0 while the test reports 1.0; a solo speaker corrected `−6 dB` against an
inactive lav corrected `+6 dB` loses 12 dB of the margin the validator accepted.

**Accepted, and it moved three defaults.** The correction stays outside the share — folding
it into the weights would count track-relative level twice, since `score_permille` already
carries it — but the invariant is now stated and tested over what is *applied*:

- `Σ g_t = 1` exactly (the share), **and**
- `c_min ≤ Σ (g_t · c_t) ≤ c_max`, where the bounds are the correction clamp itself.

The config validator's achievability bound gains the erosion term:
`20·log10(min_active_share / room_tone_share) − 2·max_level_correction_db ≥
solo_attenuation_margin_db`. With the plan's original numbers (0.5 / 0.02, clamp 12 dB) that
is `27.96 − 24 = 3.96 dB` against a 20 dB margin — the configuration the plan proposed would
have been *refused by its own validator*, which is the finding stated arithmetically.
`room_tone_share` drops to 0.005 and the clamp to 6 dB, giving `40 − 12 = 28 dB` of
guaranteed headroom. Lowering the floor costs nothing during silence, where all six weights
are equal and the shares are `1/N` whatever the floor's absolute value is.

The related claim that the correction "scales the slew rate" is true and harmless: `c_t` is
constant in time, so the applied rate is the share's rate times a time-invariant constant and
no discontinuity can arise. Stated rather than left to be re-derived.

### 2. Critical — the new cache omitted INV-08's incomplete-entry proof

The plan promised hits and identity invalidation but never truncated the intermediate.
INV-08 requires a *size* check, not merely the presence of the file the entry names.

**Accepted.** The cache tests follow `test_derivatives.py`'s existing shape: a truncated
WAV, an orphaned sidecar, a self-inconsistent one, a declared-size mismatch, and a source
mutated before the mix commit point leaving **no** sidecar — globbing the whole downstream
region under `work/cache`, not the one directory this milestone added. That last clause is
verbatim the lesson INV-08 already records.

### 3. Critical — the memory proof could not detect a materialized envelope

The plan recognized that a four-hour envelope is ~690 MB and then proposed a proof that only
requires an audio write before the last audio read. A renderer that builds all 690 MB of
gains first and *then* interleaves reads and writes passes that test.

**Accepted, and it is the best finding in the review.** The envelope enters the same ordered
event log: a write happens before the last envelope chunk is *produced*, and no chunk exceeds
the bounded control-frame size. Bounding the audio path says nothing about the gain path —
the same argument INV-07 already makes about bounding one component.

### 4. Critical — the INV-04 claim was false as written

`control_rate_hz` dividing 48000 makes samples-per-frame integral. It does not make a
configured millisecond value an integral number of control frames: 800 Hz divides 48 kHz, and
an 11 ms attack is 8.8 frames.

**Substance accepted, framing disputed.** INV-04 is about timeline arithmetic and fractional
frame rates, and the mix introduces neither — so this is not an INV-04 violation. But every
correction is right and cheap:

- `attack_ms` and `release_ms` are validated to land on whole control frames
  (`ms · control_rate_hz % 1000 == 0`), refused otherwise.
- Candidate endpoints floor the start and ceil the end onto the control grid — the same
  covering rule as `resample.to_derivative_interval`, for the same reason.
- The final partial control frame is stated, and per-sample interpolation is clipped to
  `duration_samples`.
- Durations compare as integer samples, never as floats. (See finding 6.)

### 5. Critical — INV-01 coverage for the two new composed commands was incomplete

The plan added `mix` and `process` only to the cleanup/symlink test. INV-01 also requires
full-run hash equality and a source corrupted mid-flight, for every composed path.

**Accepted**, with the sharper half of the finding accepted too: with three commit points, a
transcript failure *before* the ASR commit means nothing re-verifies the sources after the
mix read them. `process` therefore performs an unconditional final `verify_unchanged` before
report finalization, on the success path and the failure path alike, and a test mutates a
source after the mix commit and before the transcript failure.

### 6. High — FFprobe duration is not decoded duration

The gate says the MP3 is *decoded* and measured. Container and header duration can stay
plausible when decoding yields fewer samples.

**Accepted.** One decode serves both measurements:
`ffmpeg -i session.mp3 -af ebur128=peak=true -f f32le -` puts the R128 summary on stderr and
the samples on stdout; the samples are counted in bounded chunks and discarded, a clean exit
is required, and the exact count is compared against `duration_samples` as integers.

### 7. High — `process` was not proved to run independent branches, or activity once

The proposed test covered only transcription failing after a successful mix. A sequential
mix-first implementation can still abort on a mix exception and never transcribe.

**Accepted.** `process` is error-collecting rather than short-circuiting — each branch in its
own handler — and four tests say so: activity executes exactly once (spied); a mix failure
does not cancel transcribe or render; transcription success invokes render; either branch
failing still accounts for every stage and exits nonzero.

### 8. High — the strongest INV-09 tests could pass entirely through cache reuse

Rewriting the graph's prose and re-running hits the old intermediate, because the cache key
carries `attribution_cache_key` rather than the prose. And hashing the intermediate before
and after `transcribe` proves only that transcription did not overwrite that one file.

**Accepted.** The prose-mutation test runs with the cache disabled so the render genuinely
re-executes, and the structural check inspects the *transitive* import closure of
`dnd_audio.mix` in a subprocess — the technique `test_silero.py` already uses to prove Torch
is never imported — rather than grepping one directory for one string.

### 9. Medium — the silence RMS expectation was arithmetically wrong

With six equal gains of `1/N`, independent equal-power noise sums to `1/√N` of one track's
RMS, not `1/N`; perfectly correlated noise sums to exactly one track's RMS.

**Accepted.** The assertion as planned would have rejected a correct mixer or pushed an
extra attenuation into it to make a wrong expectation pass. Both cases are now tested
separately on constructed inputs, which is also the sharper statement of the gate criterion:
the point of the normalized share is that six *uncorrelated* floors do not add coherently,
and correlated ones provably cannot exceed one track.

### 10. Medium — the cache scope contradicted the stated reuse goal

ADR-0023 says the unity-gain intermediate survives a change of loudness target; the plan then
keyed it on the whole `mix` stage-config projection, so changing the target, the bitrate, a
tolerance or the retry count would re-mix six tracks.

**Accepted.** `MixConfig` splits into `mix.envelope` (control grid, attack, release, the two
shares, the correction clamp, the assertion margins) and the post-boundary encode settings
(`integrated_lufs`, `true_peak_dbtp`, `mp3_bitrate_kbps`, `mix.encode`). Only `mix.envelope`
enters the render cache identity — the same split, for the same reason, that ADR-0016 already
makes between `activity.vad` and `activity.bleed`. The encode settings reach only the MP3,
which is regenerated every run and never cached.

### 11. Medium — the charter contradicts itself about `ambiguous`

The charter's "What M3 already provides" says the bleed criterion is "about exactly these"
ambiguous candidates. The working plan keeps an ambiguous genuine speaker audible.

**Accepted; the charter's prose is wrong and is amended.** Under ADR-0014 and M3's own
closeout, `ambiguous` marks a candidate the *veto* kept because a lav hearing its wearer at
that wearer's normal level is probably not hearing someone else — the least obvious case
there is, not the most. M4's closeout says the same thing in as many words. The M5 rule is
stated plainly instead: **suppressed candidates sit at the room-tone share; every retained
candidate, ambiguous included, is eligible.**

### 12. Low by the reviewer's reckoning, but accepted in full — `work/mix.json` was over-building

The spec asks for a cached lossless intermediate and measurements in the report, not another
durable schema. The render identity belongs in a cache sidecar and the encode measurements
belong to the report; combining two lifetimes into a new artifact adds a schema, a version
and an interface **with no named consumer**.

**Accepted, and the artifact is dropped.** This is the same argument ADR-0011 used to reject
a 16-bit derivative — a choice made on behalf of milestones that have not stated a need. Per-
track corrections and every measurement go to the report's `decisions` subsection, which
INV-02 already requires to be semantically stable; the render identity goes to the cache
sidecar. Byte-stability is proved on the intermediate, which is a stronger artifact to prove
it on than a document describing it.

Removed with it: `artifacts/mix.py`, `schemas/mix.schema.json`, `test_mix_artifact.py`, and
the `MIX_RELATIVE_PATH` constant.

### Also — OQ-019 and OQ-020 were cited before they existed

## Rejected

Nothing was rejected outright. Finding 4's *framing* — that this is an INV-04 violation — is
rejected; the mix introduces no fractional rate and no accumulated float duration, so the
invariant is not in play. Every concrete correction inside that finding was taken.

## What the reviewer would change first

> "Define the actual applied coefficient — including correction — as the envelope contract,
> with exact endpoint and step-response semantics. Then build a genuinely lazy envelope
> iterator and tests over correction extremes, session-start activity, short gaps, overlap,
> correlated silence, and truncated caches. After that, separate render-cache identity from
> encoding, measure decoded sample count exactly, and implement `process` as error-collecting
> DAG orchestration rather than a short-circuiting sequence."

Adopted as the order of work.
