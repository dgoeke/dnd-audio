# M2 code review — Codex, 2026-08-02

Independent review of `git diff main...HEAD` on `milestone/M2-timeline`, run during the
verify phase. The raw transcript is gitignored; this is the distillation, with each finding
independently reproduced before it was accepted or rejected.

Verdict: *"I would not close M2 in its current state."* Six findings. **Five were real
bugs; four of those were reproduced with a concrete failing case and fixed.** The sixth
was a documentation error. One prescription was rejected with reasons.

A second, fresh-context reviewer (`feature-dev:code-reviewer`) reviewed the same diff in
parallel and reported no findings above its confidence threshold, but flagged one
sub-threshold defect that was real and is also fixed.

---

## 1. INV-01 silently omitted raw files from integrity checking · **accepted, fixed**

`raw_guard.snapshot` excluded any path whose *any* component was named `work` or `output`,
rather than only the session's own generated directories. Reproduced:

```
snapshot contains: ['raw/tx-a/one.wav']
  raw/tx-a/work/notes.txt hashed: False
  raw/output/take2.wav hashed:   False
```

Both files sit under a protected source root and neither was hashed, so mutating either
passed `verify_unchanged` unconditionally — the invariant's proof was vacuous for that
subtree. This is the precise shape M1's closeout warns about: *"an invariant check can be
present, look right, and verify nothing."* It is also **inherited code**: the helper was
moved verbatim out of `inspection/runner.py` during M2, so M1 shipped with the same hole.

Now excluded at the session root only. `test_raw_guard.py::test_a_source_under_a_directory
_named_work_is_still_hashed` builds exactly this tree, asserts both files are in the
snapshot, mutates one, and requires the failure.

## 2. Rollover inference is a heuristic, not a proof · **accepted in substance, framing rejected**

ADR-0009 claimed the widest-gap analysis made the day assignment "unambiguous". It does
not. Starts at 23:00 and 01:00 admit a two-hour session across midnight *or* a
twenty-two-hour session within one day; the algorithm picks the first because it is the
**shortest arc** containing every start, not because the evidence excludes the second.

Accepted: the claim was overstated, the assumption was unregistered, and the code did not
cite it. ADR-0009 now says plainly that this is the shortest-arc heuristic, **OQ-016**
registers it, `_cycles_by_largest_gap` cites it, and the `midnight_rollover_inferred`
warning now names it in the operator's own diagnostic.

Rejected: the framing as an INV-12 violation. INV-12 governs the case where *no reliable
timecode can be extracted*; here a timecode was extracted and only its day is inferred,
which the spec explicitly permits ("may infer a single forward midnight rollover"). The
behaviour is right and the record was wrong.

## 3. `nudge_later` and later gaps · **finding accepted, prescription rejected**

The reviewer observed that with evidence intervals A `[0,2)`, B `[1,3)`, C `[4,5)`, B is
nudged to `[2,4)` and the real gap before C disappears — and proposed propagating a
cumulative shift so C moves to 5.

The observation is correct and was reproduced. The prescription is rejected: shifting C
would move a chunk whose own timecode is *good*, misaligning it against the other five
transmitters to preserve one track's internal spacing. In a pipeline whose entire purpose
is cross-track synchronization, that trade runs the wrong way. The gap is consumed by B's
own tail, which is inherent to nudging — the only alternatives are trimming B, which the
spec forbids, or misaligning C.

So the *code* was right and **ADR-0010 was wrong**: it claimed `nudge_later` "shifts
everything after the overlap". Corrected, with the gap-consumption consequence stated
explicitly, and pinned by two new tests — a three-chunk case asserting C keeps its own
evidence position, and a cascade case where a nudge that still overlaps moves the next
chunk in turn.

## 4. A shifted timeline recorded an origin it did not have · **accepted, fixed**

With absolute evidence at 19:00 and a signed offset reaching a second below it, the whole
timeline shifts — but `SessionZero.since_day_origin_samples` still recorded 19:00.
Reproduced: the absolute source landed at sample 48000 while the artifact declared session
zero to be 19:00, so sample 0 was really 18:59:59 and every mapping from a session sample
back to wall clock was wrong by exactly the shift. Nothing downstream could have detected
it — a uniformly one-second-late transcript looks like a correct transcript.

Fixed by subtracting the shift from the recorded origin. `test_origin.py::test_a_shifted_
timeline_records_the_origin_it_actually_has` asserts the only consistent reading: zero plus
the absolute source's placement equals that source's own time of day.

## 5. Self-inconsistent cache sidecars were accepted as hits · **accepted, fixed**

`_read_sidecar` validated the key and then the size of the file *the sidecar named*, while
the runner reads the *canonical* path. Reproduced: a sidecar naming a decoy file, declaring
44100 Hz, and carrying a record version this code has never written was granted a hit.

Now the record version, sample rate, and canonical path are all validated, and `get()`
takes the caller's expected output length. Five new cases in `test_derivatives.py`.

## 6. The charter's proof table named a test file that does not exist · **accepted, fixed**

The report-behaviour row cited `tests/test_ingest_report.py`; the tests are in
`test_ingest_run.py`. The row now names the classes that actually exist and records the
correction, so the ledger does not overstate its own evidence.

## From the second reviewer

**`syncqa._derivative` opened a file twice** · *accepted, fixed*. It called
`PcmReader.__enter__` itself and returned the reader, and every caller then used it in a
`with`, entering it a second time. `__enter__` unconditionally reopens the file, so the
first descriptor was dropped without being closed. No audio impact and no test would have
caught it; the function now returns an unentered reader and lets the `with` own it.

That reviewer separately traced `Decimator`'s state arithmetic for block sizes above and
below the decimation factor and confirmed the flush loop terminates, hand-traced
`_cycles_by_largest_gap`'s tie detection, and checked the reader's interval arithmetic for
off-by-ones — reporting nothing in any of those. It also independently verified that
`test_rasterize`, `test_origin`, and `test_timeline_truth` derive their expectations from
longhand `Fraction` arithmetic or from the generator's declared truth rather than from the
pipeline's own output.

## Rejected without change

- **`to_derivative_interval` / `to_source_sample` are called only from tests.** They are
  the 48↔16 kHz mapping contract the charter requires M2 to *define* for M3 and M4, they
  are complete and tested, and the artifact's own documentation points at them. A contract
  its first consumer has not been written yet is not a placeholder.

## Deferred

- **`TrackReader` holds one file descriptor per audio segment.** Bounded in practice — DJI
  splits a four-hour session into a handful of chunks — but a session with thousands would
  exhaust the limit. Recorded in the closeout rather than fixed, since no plausible session
  reaches it and a pool would add complexity for a case that does not exist yet.
