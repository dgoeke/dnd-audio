# M4 plan review — Codex, 2026-08-02

Independent critique of M4's working plan, taken before any code was written
(`./scripts/codex-review.sh plan 4`). The raw transcript is gitignored; this is the
distillation, with the implementor's response to each finding.

**Verdict given:** *"The plan is not ready to implement as written."* Eight findings plus
three over-building notes. **Six accepted, one accepted with its reasoning rejected, one
rejected.** The three over-building notes are all accepted.

---

## Critical

### 1. `run_activity` cannot be composed under an outer cache transaction

The plan said to compose `run_activity` unchanged while also promising one snapshot and a
single verify-then-commit point for the whole run. `activity/runner.py` already verifies and
commits four cache families before returning, so a source changing during ASR would leave
them committed — the reviewer calls this the INV-08 failure M2's closeout describes.

**Accepted in its conclusion, rejected in its reasoning.** The reasoning is wrong: those four
entries were verified against the snapshot *before* they were committed, and ASR reads only
`work/`, never `raw/`, so a later mutation cannot poison them. INV-08 asks that an entry be
committed after verification, which `run_activity` does.

The conclusion is right anyway, for a different reason the review surfaced: the plan's file
list did not include `activity/runner.py`, and it had to. A composed run needs one snapshot
(not two full hashes of every raw byte), one output-rejection check over the union of both
stages' outputs, and one report covering five stages rather than two reports. So
`run_activity` splits into a composable `perform_activity` — build, detect, attribute, return
**staged** caches — and a thin `run_activity` that keeps the snapshot, the verification, the
commit, the report, and the CLI's failure handling.

**And the single transaction the review recommends is rejected.** Two commit points are kept:
activity commits after the first verification, ASR after the second. One transaction would
discard verified, expensive inference caches because something unrelated failed afterwards.
The cost is a third hash pass over `raw/` per composed run; the benefit is that an ASR failure
never costs six tracks of re-detection.

## High

### 2. "Assign words by start time" does not stop padding duplicates

Two requests sharing padding can each return the same boundary word at slightly different
timestamps — 99 in one, 101 in the other — and a rule keyed on the word's start keeps both.
Worse, an alignment-failed `segment_only` result has no word times at all, so the rule cannot
place its text.

**Accepted.** The plan asserted a property it had not established. Three rules now, each
tested:

- A word belongs to the core containing its **start**; a word inside padding but inside no
  core is dropped. Cores that are not truncation children are separated by real VAD silence,
  so this loses only a word the detector already missed, and the charter is explicit that
  padding is context rather than content.
- **At a truncation stitch boundary only** — the one place two cores are genuinely adjacent —
  a word from the later child is dropped when its normalized text equals the earlier child's
  last kept word *and* the two intervals overlap.
- A result with no words is `segment_only`: the returned text is kept whole against the core,
  with a warning, because trimming it is impossible and dropping it loses speech. That the
  text may include padding is a recorded limitation, not an oversight.

Tests return shifted duplicates from both sides and a wordless result whose text covers
padding, rather than the same timestamp twice.

### 3. Merging candidates destroys the mapping collapse and provenance need

Requests merge adjacent candidates, but `CandidateEvidence` is measured between *original*
candidate pairs and `transcript.json` records one `source_candidate_id`. If A1 and A2 merge
and B overlaps only A2, collapsing the merged result against B either deletes A1 or leaves
A2's duplicate. "Keep the best `score_permille`" is undefined for a multi-candidate record.

**Accepted, and it changes the design.** **Requests merge; ownership does not.** A request's
padded window and core span several candidates, but each candidate keeps its own ownership
subinterval, and words are assigned to the candidate subinterval containing their start. One
retained candidate produces one segment, so `source_candidate_id` stays singular exactly as
the spec's baseline has it, the score comparison is unambiguous, and collapse reads the exact
pairwise evidence M3 measured. No spec amendment is needed, which is the better outcome.

The degenerate case is real and handled: a wordless (`segment_only`) result spanning several
candidates cannot be split, so it emits one record carrying every contributing candidate id.
The records artifact therefore holds `source_candidate_ids` as a list — length one in every
ordinary case — and collapse aggregates **conservatively**: every existing cross-pair must
meet `min_correlation`, not merely the best one, because the bias is toward keeping speech.

### 4. The content-addressed ASR cache collides for a scripted fake

`ScriptedTranscriber` selects its response by `request_id`, while the planned key was the
audio hash. Two requests with identical PCM and different scripted responses share a key, and
the first answer becomes a false hit for the second.

**Accepted.** In production the collision is harmless — identical audio under identical
parameters *should* yield identical text, which is the premise of caching at all — but a fake
that is not a function of its input turns it into a test that lies, and the tests are the
proof this milestone rests on.

The fix follows `config.py`'s own stated bias, that the failure mode of a too-broad key is
recomputation while the failure mode of a too-narrow one is silent: the request's identity
(track and core interval) joins the audio hash, the transcriber identity, the context hash,
the language, and `max_new_tokens`. INV-08 requires a key to *include* the spec's list, not to
be limited to it, and identical audio at two positions does not occur in a real session, so
the added component costs nothing measurable.

The self-referential `raw_result` is also dropped. `TranscriptionResult` carries
`public_document`, the adapter's lossless serialization of its *backend's* public result,
`None` for a transcriber whose result is already its own public form; the raw artifact is an
envelope that records which of the two it holds.

### 5. New model-behaviour assumptions have no registered open question

Padding for word recovery, timestamp stability across overlapping requests, whether a
low-energy split helps a truncated response, retry counts, and text-similarity thresholds are
all assumptions about a model, and neither OQ-009 nor OQ-017 covers them.

**Accepted without reservation** — this is the project's own rule and the plan promised
compliance it could not deliver. **OQ-018** is registered before the constants land: what
Qwen3-ASR and its aligner need at a request boundary, settled by M6b. Request-shaping defaults
cite OQ-018, acoustic duplicate thresholds cite OQ-017, and `max_segment_s` keeps citing
OQ-009.

## Medium

### 6. The truncation and cap tests miss the dangerous cases, and "bounded" is ambiguous

The cap test covered a core longer than the cap but not a short core whose *padding* pushes it
over, nor the children a retry creates. Recursive splitting can make
`max_truncation_retries = N` mean up to `2^(N+1) - 1` submissions.

**Accepted.** `max_truncation_retries` is now a **global budget of additional submissions per
original request**, not a depth. A child core shorter than the configured minimum is not split
again; the split point is strictly interior, so progress is guaranteed and "no interior
low-energy point exists" cannot arise — the midpoint is always available and the energy search
only chooses among interior candidates. Every child request is capped like any other. Fallback
is **atomic per original request**: if any descendant is still truncated when the budget runs
out, the original response is kept with `asr_truncation_unresolved`, rather than a
half-stitched mixture. Both missing cap cases get tests.

### 7. Ratio thresholds should not open a second floating-point decision path

`min_overlap_ratio` and `min_text_similarity` had no stated numeric type.

**Accepted.** Configuration keeps floats, as every other threshold in this project does, but
no decision is made on one: temporal overlap compares by integer cross-multiplication against
the sample counts, and text similarity is quantized to per-mille through
`activity.to_permille` — the project's one ratio-rounding rule — before it is compared or
recorded. The public-time proof now runs on a sample position that is *not* millisecond
aligned and asserts the value `public_seconds` produces, rather than counting decimal places.

### 8. Several explicit spec requirements have no named proof

Language defaulting and overriding, the glossary being passed exactly and its absence not
blocking, `max_new_tokens` and the context hash reaching report provenance, transcriber
identity in the report, and records that declare which graph and configuration they describe.

**Accepted; all five become named tests.** The records artifact carries `config_hash`,
`timeline_sha256`, and the graph's `attribution_cache_key`, so a records file beside a graph it
does not describe is detectable rather than merely unlikely.

The related charge that the charter overclaims — that M4 cannot prove lossless serialization
of Qwen's `ASRTranscription` while real Qwen is out of scope — is **accepted**. M4 freezes and
tests an opaque JSON-preservation contract; M6b's charter gains the obligation to prove its
adapter fills it from every public field.

## Over-building — all three accepted

- **`activity --fake-models` is dropped.** It changes a closed milestone's user-facing surface
  without serving M4's gate. `run_transcribe` injects the scripted detector through the seam
  that already exists, and the flag stays scoped to `transcribe`.
- **Only alternatives actually rejected are recorded**, with the evidence behind each. Every
  evaluated pair would be quadratic artifact growth for no audit value.
- **The records/render version stays out of the ASR cache key.** Re-rendering must never cost
  a re-transcription; the raw cache depends on inference semantics alone.

---

## What the review endorsed

The 16 kHz derivative as the ASR grid, records as a pure render input, one request in memory
at a time, and the conservative three-factor collapse. Its closing summary — *"the blockers
are primarily transaction composition and missing semantics at request boundaries"* — is a
fair description of what was wrong with the plan.
