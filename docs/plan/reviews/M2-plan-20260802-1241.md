# M2 plan review — Codex, 2026-08-02

Independent critique of M2's working plan before implementation, per `AGENTS.md`. The raw
transcript is gitignored; this is the distillation, with the implementor's response to
each finding.

Verdict: *"not ready to implement unchanged; the overall architecture is sound"*, with
four P0 findings. Nine of ten findings accepted, one rejected with reason.

---

## P0 — `ingest` could construct a timeline from a stale manifest · **accepted**

The plan let `ingest` reuse `work/manifest.json` on a `config_hash` match alone. Replace a
WAV, delete a chunk, or add one without touching `session.yaml` and every hash stays
internally consistent; the INV-01 snapshot passes too, because the mutation happened
*before* the run. The timeline would then be built from stale paths, hashes, sample
counts, and timing evidence — an INV-08 violation.

The spec settles it directly: `ingest` is defined as "run `inspect` as needed, then
construct/cache the Milestone 2 timeline maps". So `ingest` now **always** runs discovery
and hashing, served by M1's content cache so a warm run costs no FFprobe. Only after a
current manifest exists may a prior report's inspect provenance be reused. This also
simplifies the report question: the `inspect` stage genuinely ran, and `origin: reused`
records that every source came from cache.

## P0 — Fractional-rate rollover arithmetic was undefined and wrong · **accepted**

"Add a single day" is not one operation. Verified independently:

| Domain | 24-hour cycle | Real seconds |
| --- | --- | --- |
| BWF sample reference | `86400 × file_rate` samples | 86400 exactly |
| Timecode, 30F / 25F / 24F | 2 592 000 frames | 86400 exactly |
| Timecode, **29.97F non-drop** | 2 592 000 frames | **86 486.4** |
| Timecode, 29.97DF | 2 589 408 frames | 86 399.9136 |

Adding 86 400 s at 29.97 non-drop misplaces the wrapped chunk by 86.4 s and manufactures a
large false overlap. The spec's timecode section says "Define 24-hour wrap handling" and
this is what that sentence is for.

Rollover now unwraps **in the evidence's own domain** — whole sample cycles for a BWF
reference, whole code cycles in frames for a timecode — before any conversion to seconds.
ADR-0009 carries the table. Rollover is tested crossed with 23.98F, 29.97F, and 29.97DF.

A consequence the reviewer did not name: at a fractional non-drop rate a timecode day and
a real day differ, so timecode `00:00:00:00` is not real midnight. A session mixing BWF
and timecode evidence at such a rate rests on an assumption about where the recorder was
jammed. That is now a recorded warning and **OQ-015**.

## P0 — Cache identity and publication did not satisfy INV-08 · **accepted**

The proposed derivative key omitted the segment-map identity, `INSPECTION_SEMANTICS_VERSION`
(a parser fix changes the *timing evidence* while source bytes and configuration are
unchanged, so an aligned derivative could be served at its old position), the PCM-reading
semantics, SciPy/NumPy identity, and any identity at all for the optional 48 kHz artifact.
All are now in the key.

The plan also had no test that a cache write is atomic or that a truncated entry is
rejected, both of which INV-08 states outright. The derivative is published temp-then-
rename, its sidecar committed only after the audio lands, and both a truncated audio file
and an orphaned sidecar are tested to read as misses.

## P0 — The memory proof only bounded one reader · **accepted**

Asserting that `TrackReader` never requests more than a window says nothing about a
derivative builder that collects every window before writing. The test would pass with the
whole path session-sized in RAM.

The proof is now a property of the *whole* path: source reads and sink writes are logged to
one ordered event list, and the test asserts a write occurs before the final read. Nothing
that accumulates a session-length array can satisfy that. It runs over a timeline far
longer than the window — cheap, because a long gap costs a long derivative and almost no
source bytes. `sync_qa.window_s` is bounded too.

## P1 — The serialized mapping contract was a list of class names · **accepted**

M3 and M5 consume this; "`Timeline`, `TimelineSegment`, `DerivativeRecord`" is not a
contract. Every question the reviewer raised is now answered field-by-field in the charter:
half-open intervals, both the rasterized and the nudge-adjusted start retained, gaps as
explicit silence segments, per-track end plus one session-wide aligned duration, the
`ceil` length rule, and the FIR's padding, phase, delay, and valid extent recorded.

**Resampling runs across the whole virtual track and is never reset at a chunk or gap
boundary**, which the reviewer was right to ask about explicitly. Tested at every input
length residue mod 3, at first and last samples, across gaps and chunk boundaries, under
varied window partitioning, and for streamed-versus-one-shot byte equality.

## P1 — Negative recovery offsets were silently disabled · **accepted**

The spec permits a *signed* `start_offset_samples`; "audio before session zero is fatal"
narrowed the input contract, and the planned override tests could have passed using only
positive values.

Split by branch instead. With an explicit `origin_timecode` the operator has asserted where
zero is, so audio before it is fatal. Without one, session zero is *defined* by the
earliest valid source start, so all placements are computed in an intermediate coordinate
system and shifted so the earliest is zero — signed offsets keep their full meaning and
relative distances are exact. Both branches are tested with negative offsets, as is a
mixed absolute/relative session and its contradiction case.

## P1 — Report behaviour had no gate proof · **accepted**

Added: fresh-versus-reused stage status, preserved inspect warnings and decisions, current
manifest and timeline deliverable hashes, changed raw input forcing re-inspection, each
mismatch case, and a fatal run invalidating a previously successful `timeline.json` —
that last one **starting from a stale timeline already on disk**, since starting from an
empty directory is the exact failure M1's closeout called out.

The plan's INV-13 paragraph was also self-contradictory about the illegal-report-location
case. Reworded: INV-01 wins there and nothing is written.

## P1 — ADRs and OQs were deferred until after coding · **accepted**

`scripts/check_plan.py` was already failing on the charter's forward references. The
decisions were made at plan time, so the records are written at plan time: ADR-0008
through ADR-0011 and OQ-014, plus OQ-015 from the rollover finding.

## P1 — Rollover depends on the filename sequence (OQ-003) · **rejected**

It does not, and it must not. INV-12 forbids deriving timing from a filename, and
`inspection.starttime.SourceContext` deliberately carries no filename so a strategy
cannot reach for one. M2's rollover inference is driven by the time evidence alone: a
chunk whose since-midnight value falls below session zero's, where the span stays inside
one cycle. The charter's phrase "chunk sequence" means the chunks' order *in time*, not
DJI's `MIC###` counter. This is now stated in ADR-0009 so the next reader does not
re-derive the coupling.

## P2 — Two tests did not prove their clauses · **accepted**

The absence of `work/timeline.json` does not prove a 44.1 kHz source failed *before*
construction — the layout builder, PCM reader, and derivative writer are now spied on and
proven un-entered, starting from a stale timeline on disk.

A calculated preflight does not settle OQ-013, which asks for measured full-pipeline disk
use from a full real session. M2 replaces `doctor`'s guessed threshold with a number
derived from the session's actual length and contributes measurements; it does not close
the question. The charter's "settles OQ-013" is corrected to "partially answers".

## P2 — The drift fixture tested metadata movement, not drift · **accepted**

Moving per-track `bext` values makes the drift test pass because the metadata moved, never
exercising cross-correlation on acoustic lag. The fixture now holds nominal timecode
placement fixed and moves the **end transient within the audio samples**. A no-clap,
low-correlation case is added so noise cannot become a confident sync result.

## P2 — Integer PCM decoding was scope creep, and one claim was false · **accepted**

Verified: `2147483647` as float32 is `2147483648.0`, so s32→float32 is *not* exact —
float32 carries 24 mantissa bits. Calling it lossless was wrong.

M2 now reads only the specified mono float32 RIFF/RF64 format and fails other encodings
with a named error. Integer formats arrive when a real recovery need justifies them.

## Ordering

The reviewer's recommended sequence is adopted: records first, then the mapping contract,
then unconditional inspection, cache identity, origin/layout, the reader and decimator,
the memory and equivalence proofs, CLI and report orchestration, with optional 48 kHz
materialization last.
