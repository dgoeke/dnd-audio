# M7a code review — 2026-08-04 19:11

**Reviewer:** independent Codex CLI, read-only review of the milestone branch against `main`
**Verdict:** *not ready to close.* Eleven findings, four P0. **All eleven accepted and fixed.**

The gate was green, 2 617 tests passed, and the milestone looked finished at the point where
all eleven were present. Four could produce a confidently incomplete archive, write into
protected sources, or preserve wrong track attribution — and several of the rest are proofs
that only appeared to prove something, which is the failure mode this repository's closeouts
record more often than any other.

## P0 findings

1. **A missing configured source root was silently skipped.** `build_source_set` did
   `if not directory.exists(): continue`, so an unmounted disk or a renamed directory meant
   the upload archived the tracks that remained and **committed successfully**. That is the
   worst outcome this milestone has: the operator is told the session is safe.
   **Fixed** — an absent or non-directory root is now `archive_source_root_missing` and
   nothing is uploaded. The reviewer also noted the narrower case, one file vanishing inside
   a root that still exists, which no check covered: `_require_nothing_vanished` now
   cross-checks the source set against inspection's own inventory, since `manifest.json` is
   the only record of what was there before. A file that *appears* after inspection is
   deliberately still fine — that is an operator dropping in a notes file.

2. **The CLI never passed `protected_session_dirs`, so `restore` could write into `raw/`.**
   The runner's refusal existed and had a test, but the test supplied the protection list by
   hand and the real wiring was empty — `archive restore --to SESSION/raw/anywhere` would
   have staged and published beneath a source root (INV-01). Separately, every archive
   report was written without `reject_outputs_inside_raw`, so `work -> raw/tx-a` meant a
   report written through the symlink.
   **Fixed** — `_sessions_above()` resolves protected sessions by walking up from the
   destination, and the report path goes through the same INV-01 check `inspect` has used
   since M1, with INV-01 outranking INV-13 when the report's own location is the violation.

3. **Existing manifests were compared on only `(path, sha256, size_bytes)`.** `track_id`,
   the codec recipe and the session id were all ignored, so reassigning track ids between
   directories and re-inspecting produced "already archived, identical content" while the
   committed manifest kept the old attribution — and `--track` recovery then returned
   another speaker's audio. An INV-11 violation reached through an equality check, and a
   direct contradiction of ADR-0038.
   **Fixed** — `_identity()` compares session id, archive version, the full codec recipe and
   every non-derived entry field including `track_id`. The compressed size and digest stay
   out and nothing is lost by it: v1's recipe is frozen and single-threaded, so identical
   sources under an identical recipe produce identical bytes, and comparing them would mean
   re-compressing a whole session to find out whether anything changed. `status` had the
   same defect and the same fix.

4. **The INV-01 end-of-operation check was missing on several exits, and the test that
   claimed to cover it did not.** The existing-manifest path returned before
   `verify_unchanged`; so did failures after the source set was built. Worse, the
   "source changes mid-upload" test completed an upload, mutated a file *afterwards*, and
   actually exercised existing-manifest divergence — it would have passed with the
   pre-commit verification deleted.
   **Fixed, and then fixed again.** The first rewrite mutated a file the loop had not yet
   reached, so `_compress_and_check`'s own re-hash caught it and the test *still* passed
   with the check removed — the same defect one layer down, confirmed by deleting the call
   and watching it stay green. The test now mutates the **first** entry after it has been
   compressed, uploaded and read back, so nothing revisits it and only the pre-commit check
   can see it. Verified by deletion: the check gone, the test fails.

## P1 findings

5. **Reports vanished on ordinary failures.** The lock was acquired outside the reporting
   boundary, so contention raised out of `run_upload` and the CLI wrote nothing — the
   failure an operator is most likely to hit produced nothing to read. `run_status` and
   `run_list` had no failure handling at all. **Fixed**; every operation now returns a
   failed report, and lock contention has its own test.

6. **`max_attempts: 1` does not disable botocore's retries — and the test certified the
   bug.** In botocore, `max_attempts` counts retries *after* the initial request, so every
   project-level attempt could make two SDK attempts and the "one bound" ADR-0038 promises
   was two. The test asserted the literal string `"max_attempts": 1` appeared in the module,
   which confirmed the mistake rather than the behaviour. **Fixed** — `total_max_attempts:
   1`, and the test now constructs a client and asserts on botocore's *resolved* retry
   configuration.

7. **Multipart recovery state was unusable for long keys, and a failed abort lost it.**
   Encoding a valid 296-byte object key produced a 313-byte filename, past the 255-byte
   component limit — so multipart failed before its first part on exactly the long paths the
   1024-byte key limit permits. And `_abort` swallowed failure while the caller deleted the
   record anyway, orphaning a billable multipart upload whose id nothing could recover.
   **Fixed** — records and lock files are named by digest, `_abort` returns whether it
   succeeded, and the record survives a failed abort so the next run retries it.

8. **"Symlink at every component" was not actually implemented.** Upload checked the roots
   and the entries beneath them but not the session directory itself; restore checked only
   `destination.is_symlink()`, so a symlinked *parent* was accepted. **Fixed** in both
   directions, with the restore side walking every ancestor.

9. **Four advertised proofs only appeared complete.** The compression interleaving test
   reimplemented `compress_file`'s loop in the test, so the production compressor could
   buffer the whole source and it would stay green. The composed restore test observed
   remote reads and never destination writes. No ENOSPC tests existed despite the charter
   requiring them at every phase. And the provider smoke exercised raw `put`/`get`/`list`
   but never `run_upload`, the manifest commit, `run_verify` or remote-only `run_restore` —
   so it did not prove the completion gate's remote-only restore claim at all.
   **All four fixed.** `Path.open` is patched so the real `compress_file` is instrumented —
   verified by making the compressor buffer and watching the test fail; restore destination
   writes are observed; ENOSPC is injected at compress, upload and restore; and the smoke
   now builds a synthetic session from generated bytes and runs upload → verify → delete the
   directory → restore, plus a track-scoped restore.

10. **Manifest discovery and report semantics were incomplete.** `list` treated any key with
    the manifest filename as a committed session without checking it existed non-empty;
    `PREVIOUSLY_VERIFIED_AT_COMMIT` was defined and never produced anywhere; `verify` and
    `restore` omitted the manifest digest ADR-0039 requires; and every recorded digest was
    computed from a reserialized model rather than the bytes that arrived, so it identified
    the model and not the stored object. **All fixed** — `_read_remote_manifest` returns the
    downloaded bytes, `list` reports unusable keys separately without calling them sessions,
    and `status` produces `previously_verified_at_commit` from the local upload report, which
    is the only honest source for a claim about history.

11. **P2 — the committed contract was internally inconsistent.** The top-level CLI help
    still said "Nothing here sends audio anywhere"; the manifest carried none of the bounded
    inspection identity the charter requires; and the charter's own proof table said to
    delete the session directory and then exercise *local* `status`, which is impossible.
    **All three fixed**, the last by correcting the charter sentence.

## What this review changed about the work, beyond the fixes

Three of the four P0s and most of the P1s are the same failure: **a check that is present,
looks right, and verifies nothing.** The plan review had already rewritten eight proofs for
this reason, and eleven more instances survived into the implementation anyway. Two were
found only by deleting the production code and confirming the test went red — which is now
the habit this milestone leaves behind, and the closeout says so.
