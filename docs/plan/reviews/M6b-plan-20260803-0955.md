# M6b plan review — Codex, 2026-08-03

Independent critique of the working plan in `../milestones/M6b-qwen-adapter.md`, run before
any code existed (`./scripts/codex-review.sh plan 6b`). Distilled from the raw transcript,
which is gitignored because a reviewer quotes every file it read.

**Verdict:** *"I would not implement this plan as written. The adapter direction is sound,
but the model-provisioning contract, revision overrides, alignment recovery, and timestamp
boundary are not yet coherent enough to satisfy the completion gate."*

Ten findings. **All ten accepted**, two of them with a narrower remedy than the one
proposed. Three were checked against the actual sources before being acted on rather than
taken at face value — the spec's own wording, the installed `qwen_asr` wheel, and
`resolve_models`' current signature. The findings removed a document amendment the plan had
proposed, changed the shape of the cache identity, restructured the backend seam, and added
five negative-case test groups and one open question.

The most valuable finding is **4**, and it is the kind only an outside reader produces: the
gate asks for a behaviour the obvious API cannot deliver, and nothing about the plan looked
wrong until someone traced the package's control flow.

---

## Accepted

### 1. Critical — a second network entry point would have needed the *spec* amended too

The plan introduced `scripts/fetch-models.sh` as a network-capable entry point beside
`models fetch`, and proposed amending the gate criterion and INV-06 to permit it. The review
pointed out that the spec itself says "`models fetch` is the only command expected to
require network access for model installation" — so the plan was changing two of the three
documents that say the same thing, which `AGENTS.md` does not permit.

**Accepted, and it removed work rather than adding it.** `dnd-audio models fetch --qwen`
shells out to the `hf` CLI instead. That satisfies everything the owner asked for — the `hf`
CLI does the download, it is one-time setup, the pipeline hard-fails without it — while the
gate criterion, INV-06 and the spec all stay exactly as written.

`scripts/fetch-models.sh` survives as a thin wrapper, because `hf` ships with the
`huggingface_hub` that lives in the ROCm environment and not in the project one, so the
command has to be run from inside the FHS shell.

### 2. Critical — checked-in file manifests cannot support a configured revision override

The plan pinned two snapshots by commit with a checked-in per-file manifest, and separately
promised `test_configured_revision_overrides_the_pin`. Those are incompatible: for any
revision other than the descriptor's, verification either rejects a legitimate snapshot or
loads an unverified one. Worse, a *mutable* configured revision cannot be resolved at all by
an offline `process`.

**Accepted.** Installation is keyed by `(repository, resolved commit)`.
`asr.model_revision` and `asr.aligner_revision` are validated as 40-character lowercase hex
commit SHAs, so a branch name is refused at configuration load — which is what makes the
gate's "use the lock rather than re-resolving a moving branch" true by construction. The
default commit verifies against the checked-in manifest; an overridden one verifies against
the lock, whose per-file digests were recorded when `models fetch` installed it.

That deliberately changes `read_lock`'s current semantics — "the lock is a convenience,
`find_model` is the authority" — for snapshots only, because for an overridden revision
there is nothing else that knows what the tree should contain. Stated in ADR-0027 and
tested, rather than left to be inferred.

### 3. Critical — "convert through `to_samples`" was not a specification

Two defects in one line. `to_samples` takes `Fraction | int`; `Fraction(some_float)`
preserves the binary approximation rather than the millisecond value the package rounded to,
which is precisely the class of error INV-04 exists to prevent. And Qwen's timestamps are
**request-relative**: a request beginning at sample 1 600 000 whose first word came back at
0.5 s would be placed near session zero and then dropped by M4's ownership rule as outside
its own core.

**Accepted.** The decoder is
`request.audio.start_sample + to_samples(Fraction(str(item.start_time)), 16_000)`, written
once, and the plan now says so rather than implying it.

The review's third point here is the one that would have cost a session: malformed alignment
must be a *recoverable* per-segment failure. Non-finite, negative, `end <= start`,
non-monotonic, or out-of-window items would otherwise fail `WordRecord` validation and abort
the entire transcript — from one bad aligner item, on a gate criterion that explicitly asks
for the opposite.

### 4. High — the proposed seam cannot retain text after an alignment failure

The gate requires that a per-segment alignment failure warn and retain segment-level text.
The plan's `QwenBackend` had one `transcribe` operation, mirroring the package's
`transcribe(return_time_stamps=True)`. Reading that method's control flow: it runs ASR,
*then* calls the aligner, and only constructs `ASRTranscription` afterwards. An aligner
exception therefore propagates out and destroys text that had already been generated.

**Verified against the installed wheel, not taken on trust** — the review cited the upstream
repository, and the published 0.0.6 wheel does the same thing.

**Accepted.** The backend seam has three operations rather than two — `transcribe_text`,
`align`, `count_tokens` — and the adapter drives ASR and alignment itself, with alignment in
its own `try`. Both are public APIs. As the review put it: a generic `TestAlignment` cannot
fix an interface that makes the recovery data inaccessible.

### 5. High — the named proofs did not prove that `process` uses the lock

The proof column named two tests, neither of which demonstrated that an absent lock is fatal
despite valid bytes, that a stale lock is rejected, that the locked revisions are the ones
reaching identity and the report, or that nothing silently falls back to the checked-in
descriptor.

**Accepted.** Four named negative-case tests replace the two.

The review's second half here is a real defect the plan did not contain a word about:
`find_snapshot` verified that pinned files were present but said nothing about *unpinned*
ones, and `hf download --local-dir` writes its own `.cache/huggingface` metadata into the
target. A stray `config.json` or custom-code file is something Transformers would load. The
tree is now an exact allowlist in both directions: `hf` downloads into staging, and only the
pinned files move into place.

### 6. High — the cache identity omitted fields, and rebuilt a vocabulary M6a had defined

The plan added `device`, `dtype`, `torch` and `hip` to `TranscriberIdentity` as flat scalars
and omitted `python` and `device_name` — while `RuntimeProvenance`'s own docstring says every
one of its fields reaches the ASR cache key, and M6a's closeout says to add them from the one
place they are defined.

**Accepted, and the review's remedy is better than the plan's.**
`TranscriberIdentity` gains a nested `runtime: RuntimeProvenance | None` instead of nine
scalars, so the cache key and the report cannot drift. A parallel flat vocabulary is exactly
what M6a's closeout warned against, and the plan had walked into it.

The second half is sharper still: `Qwen3ASRModel` takes `max_new_tokens` at *construction*
while M4 puts it on each `TranscriptionRequest`. A bundle whose identity says 512 over a
backend still generating 1024 keys a different cache entry for identical model behaviour.
The ceiling is now bound to the constructed backend and every request is asserted against
it.

### 7. High — `_default_transcriber` cannot honour configuration it is never given

Checked against the code: `resolve_models(session_dir, transcriber, detector, *,
fake_models)` receives no `SessionConfig` and no `ReportBuilder`, so the plan's claim that it
"honours configured device, dtype, revisions and attention" and "records the runtime" was not
implementable as written.

**Accepted.** `resolve_models` gains `config` at both call sites — `run_transcribe` and
`orchestrate.py` — and `Models` gains `runtime`, so the resolver's warnings survive into the
report. That last part matters more than the signature: a `device: auto` run that fell back
to CPU must carry the warning prominently, and dropping it is how an operator discovers the
fallback from a run that took nine hours instead of twenty minutes.

Also accepted: `HF_HUB_OFFLINE=1` and `TRANSFORMERS_OFFLINE=1` must be set **before**
`transformers` or `qwen_asr` is imported, not around `from_pretrained` — those libraries read
the environment at import time. And the offline test drives a deliberately incomplete local
snapshot under the socket block rather than merely asserting a variable was set.

### 8. Medium — the smoke test did not answer the questions it claimed to

Three separate gaps, all accepted:

- **OQ-018's padding question was missing entirely.** A generic short utterance shows nothing
  about whether edge words survive; it needs an utterance with known speech at both ownership
  boundaries, submitted padded and clipped.
- **OQ-009 was marked answered from source inspection alone**, when the question's own stated
  evidence is "reading the installed package **plus** a long-segment experiment". Rather than
  amend the question to excuse the omission, the experiment is now a `host_smoke` test: a
  >180 s waveform through the backend, to observe the chunking rather than quote the
  constant.
- **M4's deferred three-way collapse case cannot be decided here.** One single-track smoke
  utterance is not evidence about whether three lavs ever agree closely enough for the shape
  to occur. It stays deferred, waiting on the same real-session evidence OQ-017 wants.

### 9. Medium — real-model determinism was assumed, tested nowhere, and registered nowhere

`transcript.json` and `transcript.md` are byte-stable deterministic artifacts under INV-02.
That claim now rests on a GPU kernel: if ROCm SDPA is not reproducible across cold runs, the
artifacts stop being byte-stable the moment a cache is cleared, and nothing in the plan would
have noticed.

**Accepted.** A `host_smoke` test runs the same request twice with the cache bypassed and
compares text and word times exactly, and the assumption is registered as **OQ-022** and
cited from the adapter. Sampling is disabled explicitly rather than inherited from whatever
generation config the snapshot happens to ship.

This is the review's own best instance of its stated method — a project rule two milestones
old, quietly acquiring a new dependency nobody had written down.

## Accepted, with a narrower remedy

### 10. Medium — premature interface expansion

Two parts, both accepted, one narrowed:

**Configurable attention.** The plan gave `AsrConfig` an `attention` knob. The spec asks for
SDPA and names no second value. **Accepted as stated**: attention is hard-coded to SDPA in
the adapter and *recorded* in identity and provenance. A knob with no second value and no
consumer is interface this milestone's non-goals do not ask for.

**`test_the_adapter_calls_no_private_qwen_method`.** The review is right that this is broader
than the spec, which prohibits depending on a private *finish-reason or lower-level response*
path rather than every non-public attribute. **Narrowed** to
`test_no_private_finish_reason_or_generation_path_is_used`, which tests that specific
boundary.

The narrowing is the accepted part; the direction is not a disagreement.

## Rejected

Nothing. All ten findings survived checking, and two of them — 1 and 4 — were things the plan
could not have discovered by reading itself: one required reading the spec against the
plan's own proposed amendment, the other required tracing a third-party package's control
flow to find that the gate asked for a behaviour its obvious API cannot provide.

## What the review did not cover

It said nothing about the packaging step, the `qwen-asr` dependency closure, or the risk
M6a's closeout flags most loudly — that one AMD-only transitive requirement inside Gradio,
Flask, `nagisa`, `soynlp` or Python SoX would silently resolve from the wrong registry. That
remains the first thing to check when the lock is regenerated, and
`test_every_routed_package_is_also_a_direct_dependency` is the guard M6a left for it.
