# M1 plan review — Codex, 2026-08-02

Independent critique of M1's charter and working plan, before any inspection code
existed. Distilled from the raw session (gitignored: reviewer transcripts quote every
file they read, `LOCAL.md` included). Paths here are repository-relative.

Verdict: *"thoughtful, but I would not implement it unchanged"* — three findings at
invariant level, plus a charter/spec inconsistency.

---

## Accepted

### P0 — `start_offset_samples` was assigned the wrong time domain

The plan said every strategy in the chain yields "samples since midnight at the file's
own sample rate". That is false for a recovery offset: `config.py` and the spec both
define `start_offset_samples` as **signed, at the canonical 48 kHz rate, relative to
session time zero**. Collapsing it into a since-midnight scalar produces a wrong
timestamp whenever session zero is not midnight, and destroys the distinction M2 needs
between absolute time-of-day evidence and session-relative recovery evidence.

**Change:** the manifest carries a *tagged union* of timing evidence — BWF sample
reference, parsed timecode plus exact frame count and rate, or a signed 48 kHz offset —
and M1 never forces them into a common scalar. Recorded as ADR-0006.

### P0 — the inspection cache could serve stale semantic results

The proposed cache identity varied the RIFF-parser and manifest-schema versions but not
the naming parser, the timecode strategies, or probe parsing. A bug fix in the strategy
chain would have kept returning the old cached answer, which is precisely what INV-08's
"implementation version" clause exists to prevent. Atomic publication and
incomplete-entry rejection were also asserted rather than proved.

**Change:** one `INSPECTION_SEMANTICS_VERSION` covering probe parsing, naming, the RIFF
walk, and start-time extraction; FFmpeg and FFprobe versions varied independently in
tests; a fault-injection test that an interrupted write is never a hit; and publication
only after the source's post-inspection hash still matches, so a source changed mid-run
cannot poison the cache.

### P0 — INV-13 was argued, not proved

The plan's whole INV-13 case was that the runner calls the stage methods, so
`ReportBuilder.build()` succeeds. That says nothing about whether a report is written
when inspection *fails*.

**Change:** failure-path tests driven through the CLI — missing timing evidence,
processed-only source without permission, a required track absent, an override hash
mismatch, and an FFprobe failure. Each asserts the report exists, `inspect` is `failed`
with a structured error, the other stages are `skipped` with reasons, and the exit code
is nonzero.

### P1 — the charter claimed acceptance criterion 2 while deferring half of it

M1's `Spec sections` line claimed acceptance criterion 2, which includes midnight
rollover and final integer sample positions — both of which the plan (correctly) left
to M2. The reviewer's recommendation, which we took: M1 extracts and preserves typed
timing *evidence*; M2 normalizes dates, infers rollover, chooses session zero, and
rasterizes onto the 48 kHz grid. M1's `Spec sections` line is amended accordingly.

The reviewer also noted that a 29.97 fps frame is `8008/5` samples at 48 kHz, so
"expected integer sample position" needs a stated quantization rule. We did **not**
amend the spec for this — unlike ADR-0003 there is no impossibility, only an
underspecified rule, and it is M2's to define. Recorded in M2's charter.

### P1 — "verbatim FFprobe JSON" contradicted the chosen writer

The plan said the raw JSON is retained verbatim and, two paragraphs later, that every
artifact goes through `write_json_atomic`. Canonical reserialization changes whitespace,
key order, escaping, and the trailing newline, so it is not verbatim.

**Change:** the sidecar is FFprobe's stdout bytes written with `write_atomic`, persisted
*before* any project parsing, so it survives a parse failure.

### P1 — discovery and manifest representation were underspecified

Three concrete holes, all accepted:

- **Filename parsing must be fail-soft.** OQ-003 is open; if the assumed DJI grammar
  became an inclusion filter, real hardware could be silently omitted. A WAV with an
  unrecognized name is still a candidate and still inspected.
- **An unassigned-source collection is required.** Without one, a file in an
  unconfigured directory must either be dropped (violating per-file capture) or attached
  to a track (violating INV-11). The manifest gets a track-independent list.
- **The "file belongs to more than one apparent transmitter" warning** the spec requires
  had no named proof. It has one now.

### P1 — several proposed tests did not prove their named invariant

`test_no_manifest_field_is_time_typed` does not establish INV-03: a manifest legitimately
holds dates and durations, while a hostname or a cache count serializes as a plain string
or integer. Grepping the source for `mtime` does not establish INV-12 either — an alias
or a moved helper defeats it.

**Change:** behavioral proofs are primary. Injected clock, hostname, and cache state must
not change a manifest byte; perturbing only filesystem mtimes must change neither the
bytes nor the timing decision; and a source with no timing evidence but a plausible mtime
must still be fatal. The structural checks stay as cheap tripwires, not as the proof.

INV-01's runtime verification covers the entire `raw/` inventory, including files
inspection never selected — matching what the test snapshots.

### P1 — the report half of the gate was under-tested

The gate requires the *report* to show known/observed/per-track counts and to list
missing, empty, and extra directories, but the only named proof was a discovery unit
test.

**Change:** a typed `RosterSummary` section on the report, asserted directly and
validated against the checked-in schema, alongside the config hash, tool versions, and
the exact FFprobe argv the spec asks for.

### P2 — the fixture omitted two contracts the spec names

The spec's fixture recipe includes deterministic fake-VAD ground truth *and* deterministic
fake-ASR results. The plan had waveforms and intervals but promised neither scripted
output — cheap now, expensive in M3/M4.

**Change:** `SpeechInterval` carries a stable utterance id and text, and `FixtureTruth`
exposes both the activity spans `ScriptedActivityDetector` consumes and the transcript
script `ScriptedTranscriber` consumes.

Also accepted: pin the bit generator explicitly (`Generator(PCG64(seed))`) rather than
relying on whatever `default_rng` resolves to in a future NumPy.

### P2 — the RIFF contract needed sharper edges

Accepted in full, and it simplified the design rather than complicating it:

- `offset` is the offset of the chunk **header**, stated and tested.
- A chunk's SHA-256 covers its **complete** payload, streamed. The bounded cap limits
  *retained text*, not what is hashed — a prefix hash presented as a chunk hash would be
  a lie. The audio `data` payload is inventoried but not hashed, because the file hash
  already covers those bytes.
- `ds64` table entries for chunks other than `data` are resolved when present; a sentinel
  size with no table entry is a recorded warning.
- Truncation is **recorded and the walk stops** — not "recovered". Silent recovery from a
  malformed chunk length turns corruption into plausible but false metadata.

### P2 — the fixture's private chunk was described as DJI-shaped

Fair: that is a hardware assertion supported by nothing but a hand-built file. The chunk
is now named and documented as an arbitrary opaque vendor chunk standing in for whatever
a real device may write, citing OQ-005.

---

## Rejected, with reasons

**"Make the manifest contract the next deliverable, before probe and RIFF."** Partly
rejected. The *contract-level* decisions — the timing-evidence union and the
assigned/unassigned split — are settled now, because getting them wrong is expensive.
The leaf capture fields are not: designing them before seeing what FFprobe and the RIFF
walk actually yield would mean inventing fields that do not fit, and the manifest schema
is provisional until this milestone closes precisely so that ordering is allowed.

**"The spec should be clarified about fractional-frame quantization."** Rejected as a
spec amendment. ADR-0003 amended the spec because it stated a literal impossibility;
this is an underspecified rule, not a contradictory one, and acceptance criterion 2
becomes checkable the moment M2 documents its quantization policy. Recorded in M2's
charter instead. The spec does not change casually.
