# M8 plan review — Codex, 2026-08-03

Independent critique of the working plan in `../milestones/M8-real-session-readiness.md`, run
before any code existed (`./scripts/codex-review.sh plan 8`). Distilled from the raw
transcript, which is gitignored because a reviewer quotes every file it read — `LOCAL.md`
among them.

**Verdict:** *"I would not implement or approve this plan unchanged. It has three
top-severity timing/attribution defects, and several completion proofs do not prove the
behavior they claim."*

Ten findings. **Eight accepted outright, two accepted with a narrower remedy than the one
proposed.** Between them they change the shape of the fix to the milestone's most dangerous
function, add a session-killing defect the charter never listed, correct one completion-gate
criterion that is provably wrong, and put the spec itself on the list of documents to amend.

The two most valuable are **1** and **2**, and both are the kind only an outside reader
produces. Finding 1 shows that the planned fix to the bleed veto would have been a
*regression* in one specific case the current code handles correctly — the plan was checked
against the fixture that exercises the veto and passed, because that fixture cannot contain
the case. Finding 2 is a defect in closed M2 code that would refuse a real four-hour DJI
session outright, which nobody had looked for because the charter's list came from a run that
had only one chunk per track.

---

## Accepted, with a narrower remedy

### 1. Critical — the two-pass bleed algorithm could still delete a real speaker

The plan said a track with too few first-pass winners gets **no** reference, leaving the veto
disabled. In the gate, `reference=None` makes `vetoed=False`, so margin plus correlation can
then suppress (`activity/bleed.py::_gate`). The review produced the case:

> a quieter person who speaks **only** during overlap has no solo first-pass winners,
> receives no reference, and can be deleted during the authoritative pass.

That is the exact failure ADR-0014 exists to prevent, and the planned fix would have
*introduced* it — today's all-candidates reference lands on that speaker's own overlap
speech, fires the veto, and keeps them. `mutual_bleed_session` cannot show it, because it
gives the quieter track three solo utterances.

The review also caught an internal contradiction between the plan and the charter's own gate:
the completion test has **one** own-speech winner, while `min_reference_candidates` defaults
to **three**. The planned algorithm returns `None` for it, not the own-speech level, so the
criterion could not have been met.

**Accepted, with a different remedy.** The review's proposal — no suppression at all for a
track with too few trusted winners, marked ambiguous — is too strong in the other direction:
it makes a track that *only* ever hears bleed unsuppressible, which is the whole point of the
gate, and it breaks `delayed_bleed_session`, whose silent listener is deliberately
reference-less so that the *correlation* half is tested cleanly. What lands instead:

- The reference comes from the winners when there is at least one, under a separate floor
  `bleed.min_attributed_reference_candidates` (default **1**). A winner is direct evidence
  that this is the wearer speaking; three candidates of an unclassified mixture are not, so
  the two populations get different floors rather than sharing one. Both cite OQ-017.
- **Zero** winners falls back to the all-candidates reference under the existing
  `min_reference_candidates` — today's behaviour, which keeps the review's overlap-only
  speaker — and to `None` below that, which keeps `delayed_bleed_session`'s listener
  suppressible.
- The bootstrap reference pass 1 scores against is stated explicitly: today's
  all-candidates percentile.

The contrast test keeps its exact shape and claim by raising *both* floors beyond reach.
A new regression covers the overlap-only speaker with no solo winners.

### 2. Critical — the plan acknowledged BWF frame quantization and left the behaviour sample-exact

`rasterize.is_frame_quantized` recognizes only `TimecodeRecord`, so two chunks placed from
`bext` references get a **one-sample** overlap tolerance. OQ-004 measured DJI's references as
quantized to **1600 samples**. A perfectly normal later chunk whose reference rounds backward
is then a "material overlap" and `chunk_overlap_policy: reject` — the default — **fails the
session**.

**Accepted, and it is a defect the charter never listed.** It is the same class as defect 2:
a real DJI recording that `ingest` refuses. It is also invisible on every fixture in the
repository, because the fixtures' references are sample-exact by construction and the jam
capture has one chunk per track. Added to the milestone as **defect 2b**, with the charter
amended to say so.

The quantization is not derivable from the file — FFprobe does not surface the iXML that
declares the rate, and OQ-024 proved the receiver's configured rate does not reach an `orig`
file anyway. So it becomes configuration with a measured default:
`timecode.bwf_reference_quantum_samples`, 1600 at 48 kHz, citing OQ-004 and OQ-024, feeding
both the overlap tolerance **and** finding 4's threshold floor.

**The second half of this finding is rejected**, and the reason is recorded rather than left
implicit. The review argued that retaining the 86 400-second BWF wrap is an unregistered
assumption, since "device-local frame counter" does not imply a 24-hour period. That is
correct as stated, but removing the wrap deletes a spec-required, tested capability
(`rollover_session`, M2's gate) on the strength of a hypothesis about one vendor. The
machinery stays; the assumption is **registered as OQ-026** and cited from
`rasterize.cycle_units`, and the existing `midnight_rollover_inferred` warning already refuses
ties rather than guessing. A real DJI session never reaches the inference — its counters are
a few hundred seconds apart.

## Accepted

### 3. Critical — sync-QA compares floating-point milliseconds (INV-04)

`syncqa._assess` compares `found.lag_ms`, a float, against a float threshold. INV-04 permits
integer samples and rationals internally and floats only at the public serialization boundary.
The plan added a *second* millisecond threshold without noticing, and its invariants section
omitted INV-04 entirely. The proposed 11.31 ms and 120 ms tests sit far from any boundary, so
both would pass with the violation intact.

Configured thresholds now convert to exact derivative-sample counts once, and every
comparison is integer. Milliseconds appear only in the rendered report text.

### 4. High — the charter's "one frame at the session rate" is the wrong floor

The plan derived the constant-offset threshold from `timecode.frame_rate`, because the charter
says to. **OQ-024 proves that setting does not reach the file**: a receiver configured for
60 fps wrote `TIMECODE_RATE 30/1` on 1600-sample boundaries. A `60F` session would therefore
get a ~17 ms floor against source timing that still has a 33.3 ms quantum, reinstating exactly
the false alarm this milestone exists to remove.

**The completion-gate criterion is amended**: the floor is the largest effective quantization
among the session's own evidence — the `bwf_reference_quantum_samples` above for a BWF
reference, one frame at the configured rate for a timecode tag — not the receiver or session
setting. A 60F case joins the tests.

### 5. High — the spec is not on the list of documents to amend

AGENTS.md requires the spec to be amended in the same commit as a proved correction. The plan
wrote four ADRs and left the spec saying `orig` input is 32-bit float (line 56), that
`time_reference` is samples since midnight (436), and that origins and rollover are
calendar-day based (438). The semantic sweep was also too narrow: `rg 'OQ-004'` cannot find a
false claim that carries no citation, and examples remain in `TimecodeConfig`, the
session-config schema, the fixture helpers and `timecode.py`. Changing the manifest model's
prose means regenerating `manifest.schema.json`, not only `timeline.schema.json`.

All accepted. The sweep searches `midnight`, `calendar`, `day origin` and `absolute timecode`
as well as the OQ id, and spec, schemas, fixtures, OQ-004 and ADR-0006/0008/0009 move together.

### 6. High — transcript semantic identity is omitted

M8 changes duplicate-collapse behaviour, so two `transcript-records.json` documents both
stamped version 1 could carry different duplicate survivors and no consumer could tell them
apart. The plan bumped only the activity and timeline semantics.

Accepted, and with the review's own recommendation between its two options: **split** the
version rather than bump it. ASR request-shaping and submission semantics stay in the ASR
cache key; assembly, collapse and rendering get their own version, recorded in the records
artifact and *not* in the ASR key. A future collapse change then costs a re-render rather than
re-running GPU inference over a four-hour session. The review is right that this is cheapest
now, before any real-session cache exists — which is the whole premise of this milestone.

### 7. High — the 24-bit path has no composed memory-bound proof

The planned proofs were a two-million-value conversion buffer and a small mixed-format
session. Neither shows that a four-hour 24-bit source is decoded in bounded windows, and NumPy
has no packed 24-bit dtype, so unpacking is precisely where an implementation accidentally
expands the whole source. INV-07 asks for the composed-path proof, not a helper assertion.

`tests/test_memory.py` gains a 24-bit case in the same ordered event log: each read bounded by
the requested window, each expanded array window-sized, and a write before the last read.

### 8. Medium — dropped-word diagnostics are under-specified and under-tested

`_owned_words` runs once per candidate **group**, while one merged outcome can carry ownership
intervals for several groups — so instrumenting inside it would count B's legitimately owned
words as drops while processing A. The plan said the right thing and named the wrong site.

The count is computed once per **outcome**, across all of that outcome's ownership intervals,
in `draft_segments`. The metric is defined explicitly — dropped `(request, word)` pairs, so a
padding word two overlapping requests both return and both drop counts twice, stated in the
note itself — and the three cases the review asks for are tested: a merged outcome with two
independently owned groups, a true padding-only word, and the same padding word returned
twice. Affected candidates are structured `Decision.details`, not prose.

### 9. Medium — 8-bit WAV PCM is unsigned

The plan said "signed integer PCM at 8, 16 or 24 bits". WAV 8-bit PCM is **unsigned with an
offset of 128**, so that sentence would have read every 8-bit file at the wrong offset. A
factual error, caught before it was written.

The operator chose the principle over an allowlist, so the principle is stated in two parts
rather than narrowed: a format is accepted when it is a **signed little-endian integer or IEEE
float** *and* converts to float32 with zero error. `u8` fails the first half and is refused
with a reason that is true of it — untested rather than unrepresentable — and `pcm_s32le` fails
the second.

### 10. Medium — the `creation_time` prohibition is too broad

A structural test that `creation_time` is read *nowhere* conflicts with the charter's own note
that wall clock stays useful for archival naming and for a human reading a report — M7 is
exactly such a consumer. Accepted: the assertion is that **placement and synchronization are
invariant under wall-clock changes**, which the byte-identical-`timeline.json` test already
proves, and no global prohibition is added.

### 11. Medium — INV-02's report obligation is not proved by the plan

`ingest-report.json` is exempt from byte-stability as a whole, but its provenance and decision
subsections must be semantically stable. The new per-track activity decisions and dropped-word
decisions need their own assertion across a cold and a warm rerun, with deterministic ordering.
Added.

### 12. Minor — `attributed_candidate_count` is ambiguous after this change

The review notes that first-pass reference winners and final retained candidates are no longer
the same population, so a single field named `attributed_candidate_count` would be unreadable.
Split into `reference_candidate_count` (what the reference was measured from) and
`retained_candidate_count` (the final decision), which is also what makes finding 1's remedy
auditable from the artifact.

---

## Net effect on the milestone

Two items added that the charter did not have — **defect 2b** (the BWF overlap tolerance) and
the **transcript semantics split** — one completion-gate criterion amended as provably wrong
(5a's frame-rate floor), one invariant added to the at-risk list (INV-04), and the spec moved
onto the list of documents this milestone amends. The charter is edited to say all of it
before implementation begins, which is what AGENTS.md means by not drifting silently.
