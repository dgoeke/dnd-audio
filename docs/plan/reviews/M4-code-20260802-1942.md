# M4 code review — independent findings, and what was done about them

**Date:** 2026-08-02 · **Milestone:** M4 · **Command:** `./scripts/codex-review.sh code 4`
**Raw session:** `M4-code-20260802-1942.raw.md` (gitignored — a reviewer transcript quotes every
file it read, `LOCAL.md` among them)

Codex's verdict was **"I would not close M4"**, with eight findings. A second independent pass
by a fresh-context reviewer agent found one of the same defects independently, arriving at it
from the ADR text rather than from the code. The verifier's own mutation sweep found three
more coverage holes, two of which turned out to be the same defects from the other direction.

Every finding below was reproduced with an executed probe before being accepted or rejected.
None was taken on the reviewer's word, and one was corrected: the verifier's first mutation
run produced two false results because a same-length source edit (`min` → `max`) restored
within one second left stale `.pyc` bytecode that `(mtime, size)` invalidation could not see.
The sweep was re-run under `PYTHONDONTWRITEBYTECODE=1`. **Anyone doing mutation testing in this
repository should set that variable**; it is the second time this project has found a
verification that could not fail, and the first time the cause was the interpreter.

---

## Accepted and fixed

### 1. Failure cleanup deleted files under `raw/` (Critical, INV-01)

`run_ingest`, `run_activity` and `run_transcribe` all deleted their stale artifacts *before*
checking for `output_inside_raw`. With `work -> raw/tx-a`, the run that correctly detected the
INV-01 violation committed it on the way out — reproduced against all three commands, with a
file written into `raw/tx-a/` before the run gone after it.

Two of the three are closed milestones' code (M2's `timeline/runner.py`, M3's
`activity/runner.py`). All three were fixed here rather than deferred: leaving a demonstrated
violation of the project's hardest rule at HEAD to keep a diff narrow is not a trade this
repository makes. **ADR-0021**; INV-01 amended; `TestCleanupNeverWritesIntoRaw` parametrizes
all three composed commands from `tests/test_raw_guard.py`, deliberately in the file that owns
INV-01's machinery rather than in any one runner's tests.

The report carve-out was tested in every one of those milestones. The cleanup beside it was
not, in any of them, because each milestone's regression test named the runner that milestone
had added. That is the lesson INV-08 already records about caches, arriving a second time
about deletions.

### 2. A partial report hashed deliverables the cleanup had deleted (Critical, INV-13)

After the first commit point the composed run records `work/timeline.json` and
`work/activity.json` as hashed deliverables. Any later ASR failure deleted both while leaving
the entries and the `complete` stage statuses in place. Probe: exit 4, `activity: complete`,
`work/activity.json` hashed as a deliverable, on disk = False.

Fixed by `ReportBuilder.completed` plus a `completed=` argument to
`remove_activity_artifacts`: a stage that completed keeps its artifacts, a stage that did not
keeps nothing. `TestAPartialRunReportsOnlyWhatSurvived` asserts both directions. **ADR-0021.**

An existing test's comment — "inspection, the timeline and the graph all genuinely completed
and their deliverables are real" — was false when written; it now asserts what it claims.

### 3. Cap-split boundaries duplicated words (High)

Found independently by both reviewers. ADR-0020 called a truncation stitch "the only place two
ownership intervals are genuinely adjacent". That is false: `requests._divide` cuts a candidate
longer than `max_segment_s` into pieces that tile it exactly, each submitted as its own
independently padded request. `without_boundary_repeat` ran only inside `asr._stitch`, so a
boundary word returned at slightly different times by the two requests reached the transcript
twice. Probe: `"hello Zephyrine Zephyrine again"`.

This is the gate criterion "boundaries stitched deterministically **so padding cannot duplicate
words**" failing on the path the criterion is about. The rule now lives in one function called
from both sites, narrowed to pieces that actually share a boundary.
`TestAdjacentPiecesDoNotDuplicateAWord` covers the repeat, the genuine `"no, no"`, the
different word, and the pathological long end-time across a gap that the time-overlap check
alone gets wrong.

### 4. A merged segment was collapsed on evidence covering only part of it (High)

`_weakest_correlation` took the minimum over the candidate pairs that *existed*, silently
ignoring candidates the graph never compared. A wordless merged `A1+A2` — ADR-0017's degenerate
case, and the only reason `source_candidate_ids` is a list — could therefore be collapsed on
`A2`'s strong evidence alone, deleting `A1`'s unrelated speech with nothing in the audio to
show it happened. Probe: `"Yeah"` gone from the transcript.

Every candidate on both sides must now have been measured against the other side, or there is
no evidence about this pair of *segments*. `TestASegmentCoveringSeveralCandidates` covers the
weakest-pair rule, the all-pairs control, and the unmeasured-candidate hole.

### 5. Text similarity was order-dependent across the collapse threshold (Medium)

`difflib.SequenceMatcher.ratio` is not symmetric. Codex's pair scores 857‰ one way and 571‰ the
other against a default threshold of 850‰, so which of two lavs happened to sort first decided
whether a line was deleted. Deterministic, so INV-02 was never at risk — but a deletion
decided by an arbitrary tie-break is not a decision.

`similarity_permille` now takes the lower of the two directions: symmetric, and erring toward
keeping both, which is this module's bias everywhere. The pair is kept verbatim in
`TestSimilarityIsSymmetric` rather than reduced to a prettier example, because a prettier one
would not have caught it. The old test's name, `test_it_is_symmetric_enough_to_be_used_either
_way_round`, promised more than its single benign phrase checked, and was renamed to say what
it does.

### 6. Three coverage holes the mutation sweep found (Medium/Low)

Each is a documented, deliberate rule with no test that failed when it was inverted:

- **Weakest-vs-strongest correlation** — every collapse draft carried exactly one candidate id,
  so `min` never had more than one value to choose from. Same root cause as finding 4.
- **Start-based word ownership** — no test used a word *straddling* an ownership boundary, the
  one input that distinguishes the start rule from an overlap rule. Same root cause as
  finding 3. `TestAWordBelongsToTheIntervalContainingItsStart` covers it.
- **The Markdown timestamp** — `transcript.json` was tested on a non-millisecond-aligned
  position, `transcript.md` was not, so `timestamp()` passed with its exact rational
  arithmetic replaced by float truncation. At sample 24 the two documents would then disagree
  (`0.001` against `.000`), which the renderer's own docstring says cannot happen.
  `TestTheMarkdownTimestampIsExactToo` drives eight unaligned positions against the JSON.

### 7. The 32 ms split-energy window cited no open question (Low)

`SPLIT_FRAME_SAMPLES` claims 32 ms is long enough that a glottal pulse does not read as silence
and short enough to land inside a pause. Both halves are guesses about real speech, and every
other such constant in this milestone cites **OQ-018**. Now it does too.

## Accepted, deferred

### 8. A three-way duplicate group can keep a non-best survivor (Medium)

With A=800, B=700, C=900 all mutually duplicate, A absorbs B first and is then forbidden from
being absorbed by C, so A and C both survive. Reproduced. The module docstring says "the
survivor is the one with the best source score", and here it is not.

**Deferred, not fixed.** The failure is in the *safe* direction: it keeps both and marks them
overlapping, which is the bias the charter states outright ("bias every ambiguous case toward
keeping both and marking overlap") and which the gate criterion explicitly permits
("ambiguous evidence retains both, marked as overlap"). The cost is a duplicated line in a
transcript; the alternative — a chain-resolution pass that reorders absorptions — is new logic
in the most dangerous function in the milestone, to make a safe outcome tidier. Recorded in
M4's closeout as a known limitation with the reproducing scores, for M6b to revisit once real
ASR output shows whether three-way agreement happens at all.

## Accepted with its reasoning rejected

### 9. "INV-08 is deliberately violated by the two-commit design" (Critical → Medium)

Codex is right that INV-08's stated test — "a failed run leaves no sidecar anywhere under
`work/cache`" — is false for this run, and right that the test M4 shipped had a name saying the
opposite of what its body asserted. Both are fixed.

The reasoning is rejected. The *invariant* is "an entry is committed only after INV-01 has been
re-verified", and both commit points satisfy it: the activity caches are published after a
verification that actually happened, on bytes that run confirmed. The hazard INV-08 exists to
prevent — an entry keyed on bytes nobody checked, which matches again forever once the original
file is restored — is not created by an earlier commit point. What was wrong was a test
prescription written for a single-commit run, not the design. **ADR-0021** amends the
prescription and leaves the rule alone; the test is renamed to say which region it globs.

## Not reproduced

Nothing. Every finding was reproducible as described, which is unusual and worth saying.

## Note on the verification environment

Codex could not run `./scripts/gate.sh` — `uv` and `pytest` both need writable cache and temp
directories, and the review sandbox is read-only. That is an environment limitation rather than
a branch result; the gate was run by the verifier before and after every change.
