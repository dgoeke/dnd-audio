# M10 independent plan review — 2026-08-05 06:06

**Reviewer:** independent Codex CLI, read-only plan review
**Reviewing:** the Working plan written during M10's start phase, including the three charter
amendments (A1–A3) the operator approved on 2026-08-05
**Disposition:** ten findings — **eight accepted in full, two accepted in part, none rejected
outright.** Both P0s accepted. No implementation code existed when this ran.

Its closing sentence is worth keeping: *"The signal-generation direction itself is reasonable.
The expensive mistakes are around the command boundaries and analysis artifact contract, not
the chirp formula."* That is where every finding below lands.

## P0 — invariant violations

### 1. `marker build` could write into `raw/` — accepted in full

`marker build OUTPUT_DIRECTORY` takes an arbitrary destination and has no session argument, and
the plan gave it no INV-01 guard; only `marker analyze` joined the composed-command matrix. So
`dnd-audio marker build SESSION/raw/tx-a`, or an output symlink resolving there, writes three
files beneath a source root.

**This is the same defect M7a's second code review found**, in the same shape: a guard
conditioned on having a session directory, defeated by the one command that never has one
(`archive verify --report SESSION/raw/tx-a/<a recording>` overwrote an irreplaceable file with
JSON). The plan reproduced it in a new command while the fix for the original sat twenty lines
away in `cli.py`.

Accepted. `cli.py::_sessions_above` and `_reject_report_inside_raw` generalize into one helper
that refuses any resolved path landing under any enclosing session's configured source roots;
`marker build` uses it on its destination **before** creating a directory, writing a candidate,
or replacing anything. The regression drives the real command against a real source filename
and asserts the file's bytes are unchanged.

### 2. "Every occurrence" and "memory independent of search length" were not reconciled — accepted in full

The detector streams, but the analyzer retains every accepted occurrence on every track, forms
groups, keeps unmatched detections, and serializes them into one Pydantic document. Online
non-maximum suppression bounds *nearby* candidates; it does not bound the number of *separated*
accepted occurrences across a long or adversarial range. The lists grow with the search range,
which is an INV-07 breach on the composed path.

The reviewer also caught that the proposed proof would not have found it: one block before the
last read, plus equal peak array size across a tenfold longer *sparse* search, passes while
Python lists grow without limit.

Accepted, with the failing option rather than the spooling one: a **versioned occurrence
ceiling that fails explicitly**, never truncates, and names itself in the report — this project
does not do silent caps. Disk-backed spooling is machinery for a command whose default is two
120-second windows. The memory regression is rebuilt around **dense accepted candidates**.

## P1 — completion-gate and semantic defects

### 3. The stale-artifact validator was incomplete *and* not read-only — accepted in full

Two halves, both right, and the second is a factual error in the plan.

**Incomplete:** comparing the manifest digest against `timeline.manifest_sha256` leaves a
timeline produced by obsolete logic internally consistent with the same manifest and therefore
accepted. Every component of `TimelineProvenance` must be compared against the current
constants — `timeline_semantics_version`, `inspection_semantics_version`, NumPy and SciPy
versions — plus `Timeline.config_hash` against the currently resolved configuration, and the
schema version and sample rate against what M10 accepts. Each staleness gets its own test.

**Not read-only:** the plan said "re-run inspection **in memory** … publishing nothing". That
is false. On a cold or missing sidecar, `inspection/runner.py::_inspect_one` writes
`work/ffprobe/…`. "Warm from M1's content cache" is an assumption about the machine, not a
contract — the same class of mistake M6b's closeout records about six tests that asserted a
property of the machine rather than of the code.

Accepted, and the replacement is simpler than what it replaces: a dedicated read-only validator
built from the source snapshot the run already takes, the contents of `work/manifest.json`, the
current resolved configuration, and the loaded timeline's provenance. **No inspection run at
all.** A test asserts the entire pre-existing `work/`, `output/` and cache trees are
byte-identical after `marker analyze`.

### 4. A3 dropped a completion-gate requirement — accepted in part

Correct as a process point: the gate requires an opt-in browser smoke and requires the
local-browser bench to be separately recorded, and *a scratch section cannot override the
charter's gate*. The reviewer is also right that a parsed transition table proves the table's
graph, not that the page's JavaScript applies it, that `ended` resets the UI, or that the
embedded asset reaches playback.

**Rejected:** reinstating the dynamic smoke. Deferring it is the operator's decision, taken on
2026-08-05 against the cost of a browser in the flake or a third environment.

**Accepted:** the amendment must be made to the **completion gate itself**, in the charter,
saying what will actually be proved and what has moved to the physical bench — not left in a
scratch section that the gate then contradicts. Criteria 3 and 12 are edited accordingly, and
the reduced software proof is named rather than implied.

### 5. The event-log time and assignment contract was underspecified — accepted in full

Units were never stated; separately rounding approximate seconds into start and end samples
would be a second quantization path, which INV-04 forbids. And role assignment was undefined
where a single reference detection falls inside both a `start` and an `end` interval —
canonicalizing the searched set prevents detecting an occurrence twice but does not prevent an
arbitrary role.

Accepted, frozen in ADR-0041 before implementation: intervals serialized as integer
milliseconds and converted through `determinism.to_samples` — the one quantizer — half-open and
clamped; a matching halo of the marker's own length so an anchor near an edge is still found;
one-to-one event↔reference-occurrence assignment; ambiguity resolved as **inconclusive rather
than an arbitrary role**; playback order as the tie-break. Boundary tests one sample either
side of every interval edge, plus an overlapping start/end-event case.

### 6. Scores needed a deterministic integer representation and a complete identity — accepted in full

The plan promised a normalized score and, four sections later, that the deterministic document
contains no floats. Both cannot hold. Worse, thresholds, runner-up separation and equal-score
ties would have compared raw floats — **exactly the defect M8 removed from sync QA**.

Accepted. Scores become integer **permille**, matching the vocabulary already in use
(`similarity_permille`, and OQ-017's correlation figures); the rounding is defined once; every
threshold, separation and tie compares in that domain, with tests one unit either side of each
boundary.

Also accepted: the identity document named marker and detector versions but nothing covering
event assignment, grouping, start/end selection, geometry classification or source-coordinate
mapping — so changing one of those algorithms would change the analysis without moving its
claimed identity. It gains a distinct `marker_analysis_semantics_version`, the event-log schema
version, a canonical event-log digest, and the schema version of every consumed artifact.

### 7. The spec is wrong, and the planned amendment was too narrow — accepted in full

The spec says a changing acoustic lag *"is evidence of sample-clock drift"*, unconditionally,
in both the Milestone-2 synchronization-QA paragraph and acceptance criterion 15. That is false
when the phone or a lav moved — which is **finding 3 of the previous M10 plan review**
(`M10-plan-20260804-1735.md`), accepted into this charter and never propagated into the spec
itself. The plan's promise to "name the generated marker alongside the clap" would not have
corrected the false causal claim, leaving spec, implementation and gate disagreeing.

Accepted. Both passages gain the fixed source-**and-lav** geometry condition before a
recorder-drift warning may be emitted, amended in the same commit as ADR-0040, which is the ADR
that exists to separate exactly these four things.

### 8. Hardware-dependent constants were not fully covered by the OQ citation plan — accepted in full

Only the gap tolerance was promised a citation. The bounded cross-track association lag, the
clipping and weak-signal thresholds, the score and ambiguity thresholds, the NMS radius against
reverberation and repeats, the "material" differential-change threshold, and candidate
bandwidth survival through the phone/lav/DJI path are all empirical too.

Accepted: every one cites OQ-025 or OQ-029 while provisional, and the frozen v1 constants cite
ADR-0042 and the resolved evidence.

## P2 — scope and proof quality

### 9. The public candidate flag contradicts the charter's non-goal — accepted in part

The charter's non-goals exclude "a public candidate-management CLI", and A2 exposes
`marker build --marker cand-a` on the shipped command.

**Rejected:** driving candidate builds from a private bench script. That re-opens precisely the
gap A1 exists to close — the CLI wiring is *where M7a's P0 lived*, so a bench that stops short
of it proves the wrong thing.

**Accepted:** the shipped public surface should not advertise candidates. `--marker` becomes a
**hidden** option, documented in the bench protocol rather than in `--help`. The bench still
drives the real command through its real guards; after v1 is frozen the discoverable interface
is `marker build OUTPUT_DIRECTORY` and nothing else. A single option naming one of three frozen
registry entries is not candidate *management*, and the non-goal is honoured on the surface
that matters.

### 10. Static-page and manifest-last proofs were weaker than claimed — accepted in full

Three sub-points, all correct:

**The denylist was incomplete** — CSS `url(...)`, URL-bearing media/iframe attributes, forms,
`navigator.sendBeacon`. Maintaining a list of known network APIs is the wrong shape. Inverted:
the document is parsed, **every** URL-bearing attribute is asserted absent or a `blob:`/`data:`
the page itself generated, and the page carries a restrictive
`Content-Security-Policy` meta with `default-src 'none'`. An allowlist plus CSP, not a grep.

**Manifest-last is not a completeness marker on *replacement*.** A crash between replacing the
WAV and the HTML leaves the *previous* manifest beside a mixed set — describing bytes that are
no longer there. Accepted: the manifest is **unlinked first**, then the WAV and HTML are
written and validated, then it is published. Any interrupted state then has no manifest, which
is detectable. Interruption tests at each publish boundary.

**The `docs/fixtures/` wording was loose** — sanitized measurements, commands, hashes and
conclusions are recorded there, never the takes. That was the intent; the plan did not say it,
and this repository is public.

## Result

The plan was not ready to implement as written, and is amended above before any code. The two
P0s are both cases of a guarantee that the proposed *proof* would not have caught — a raw-path
guard that no test drove, and a memory bound whose regression used sparse input. That pattern is
the reason this project runs a plan review at all.
