# M3 plan review — Codex, 2026-08-02

Independent critique of M3's working plan before implementation, per `AGENTS.md`. The raw
transcript is gitignored; this is the distillation, with the implementor's response to each
finding.

Verdict: *"not ready to implement unchanged. Two invariant proofs are incomplete, one
fixture construction is concretely wrong, and the proposed Silero lifecycle does not fit the
existing detector interface."* Ten findings. **All ten accepted**, two in a modified form
with the difference recorded below.

---

## Critical — INV-08 was one cache where the spec requires two · **accepted**

The plan cached per-track VAD only. The spec defines `activity` as the shared cached
operation that `transcribe`, `mix`, and `process` all invoke, so bleed gating and scoring —
the expensive cross-track half — would have been recomputed on every run. Worse, the two
halves invalidate for different reasons: a changed VAD threshold must re-run inference, and
a changed `min_correlation` must not.

Split into two identities:

1. **Detection**, per track: the derivative's own cache key, the detector and model
   identity, and the VAD settings.
2. **Attribution**, per session: the sorted detection keys, the bleed and scoring settings,
   the speech-band filter identity, and `ACTIVITY_SEMANTICS_VERSION`.

The reviewer also noted the raw `uint16` probability file had only a round-trip test, where
INV-08 requires an expected-size check and atomic publication. Every incomplete-entry shape
is now tested: truncated data, a missing data file, a sidecar naming a different file, a
wrong frame count, a wrong record version, and a stale attribution entry over valid
detection entries.

## Critical — INV-13 had no end-to-end failure proof · **accepted**

`run_activity` was described as a success path ending in a report write, while at least six
expected failures precede that point: an absent model, a hash mismatch, a detector
exception, an unreadable derivative, a source mutated mid-run, and a report path resolving
inside `raw/`. The planned tests proved the *adapter* refuses bad input; none proved the CLI
then writes a valid report with `activity: failed`, every other stage accounted for, and a
nonzero exit.

Added as CLI-level tests, each starting from a **pre-existing report and graph on disk**, so
the stale-artifact case is covered rather than assumed — the failure M1's closeout warns
about.

## High — the proposed fake composition drops genuine speech · **accepted**

`activity_spans() | bleed_spans()` is a dict union: where a track appears in both mappings,
the right value *replaces* the left. `tx-d` and `tx-e` carry both genuine speech and `tx-a`
bleed, so their genuine overlap would have vanished — and the end-to-end assertion that both
survive would have failed, or silently stopped exercising overlap at all.

Concretely correct, and a good catch. `FixtureTruth.leaky_activity_spans()` now merges per
track and sorts, so no test writes the union by hand.

## High — the recurrent Silero lifecycle does not fit the protocol · **accepted, modified**

Silero carries recurrent state and 64 samples of context; `ActivityDetector.detect(window)`
looks stateless. One detector reused across tracks leaks one speaker's state into another;
one reconstructed per window makes the result depend on the window partitioning. Neither bug
is reachable by `ScriptedActivityDetector`, so the planned partition test could not have
caught either.

Accepted in full as a *problem*. The reviewer's fix was a factory returning a stateful
stream per track. **Modified:** the protocol M0 froze stays as it is, and the contract is
made explicit instead — a detector instance belongs to exactly one track, windows must
arrive contiguous and in order, and `SileroActivityDetector` **raises** when either is
violated rather than silently resetting. The runner builds one detector per track through a
`DetectorFactory` callable. This gets the same guarantees without changing an interface two
later milestones already type against, and the violation is loud rather than inferred.

The reviewer's testing prescription is adopted unchanged: partition invariance and
cross-track isolation are proved against a **stateful fake ONNX session** exercising the
production code path, not against the stateless scripted detector.

## High — the suppression rule ignored the score the gate requires · **accepted**

The plan decided suppression on `dominance_db` plus correlation, and computed the four-term
score separately, as a diagnostic. So the score could have been present and irrelevant,
which is the gate criterion satisfied in letter only.

The concrete failure is the one this milestone exists to prevent: two people genuinely
speaking at once at unequal levels, each lav also carrying the other's bleed. Dominance and
correlation are both satisfied, and the quieter *genuine* speaker is suppressed. The
canonical fixture cannot reveal it — `tx-d` and `tx-e` have no mutual bleed — and the
planned "quiet speaker survives" test deliberately made the loud signal *uncorrelated*,
which is the easy half.

Two changes. The decision now runs on the **scores**, with a required margin. And there is
an explicit veto: a candidate whose level sits within `veto_db` of **its own track's**
speech reference is never suppressed, however loud and however correlated the other track
is. A lav hearing its wearer at the wearer's normal speaking level is not hearing bleed —
which is exactly why the spec says "track-relative", and the veto is what makes that phrase
load-bearing rather than decorative. A `mutual_bleed_overlap` fixture variant carries the
reviewer's case.

## High — the frozen graph contract was underspecified · **accepted**

Naming classes is not a contract, and this one is frozen for two downstream milestones. Each
gap is now closed:

- **Lag units.** `measure_lag` returns 16 kHz samples while intervals are 48 kHz samples.
  *Modified from the reviewer's framing:* rather than scaling the lag to the canonical grid,
  which would imply precision the measurement does not have, the field is named
  `lag_derivative_samples` and the document states `derivative_sample_rate`.
- **References name the winning candidate id**, not merely the winning track.
- **Evidence is one record per compared pair**, sorted by the competitor's candidate id,
  with the suppressor named explicitly — so multiple suppressors are visible rather than
  collapsed.
- **Canonical ordering is stated for every collection**, nested ones included.
- **INV-09 gets a real enforcement.** An import test does not stop M4 adding a local
  `normalized_text: str`. A **field allowlist test** over the checked-in schema does: every
  property name in the frozen document must appear in an explicit list, so a text-derived
  field is a failing test rather than a silent contract change. The import test stays as
  well; they fail for different reasons.

The reviewer also asked for example documents written from both consumers' perspectives.
Both access patterns — M4's retained-candidates-to-request-intervals, M5's per-track
active-intervals — are exercised against a really generated graph.

## High — the plan deliberately failed the charter's Silero-package clause · **accepted**

The plan does not install `silero-vad`, which the charter and the spec both call for. The
reviewer agrees the plan is right and the wording is wrong — pinning an unused Torch-based
package buys no reproducibility and costs a dependency conflict with M6a — but is correct
that an ADR alone is not the remedy the working agreement specifies.

So the **spec is amended** in the same commit as ADR-0013, and M3's gate wording with it:
what must be pinned is the upstream release and commit, the artifact's content hash, the
ONNX interface identity, and the runtime that executes it. This is the second amendment to
the spec, after ADR-0003.

## Medium — whole-session config hashing makes tuning expensive · **accepted**

The plan claimed that extending `ActivityConfig` "correctly invalidates M2's derivative
caches". It does not: changing `min_correlation` or a score weight cannot change a single
sample of 16 kHz PCM, yet it would rebuild every derivative in the session. Tolerable for
M1's seconds of FFprobe; not for gigabytes, and OQ-017 guarantees this tuning loop gets
walked repeatedly.

Cache identities now use a **stage-scoped projection** of the resolved configuration rather
than the whole `config_hash`. The projections are deliberately generous — a field is
included unless it provably cannot affect that stage — and each is tested in both
directions: it changes when any field it covers changes, and does not change for the
sections it excludes. This touches M2's derivative identity, which is closed-milestone code;
ADR-0016 records why.

## Medium — OQ-017 was scheduled too late, and named the wrong evidence · **accepted**

The repository rule is that the question exists *and is cited from the code that depends on
it*, so registering it at closeout is backwards. OQ-017 is written before the first default
threshold, and every defaulted field cites it.

The reviewer is also right that `Needs: H1` contradicts H1's own non-goals: a two-minute
metadata fixture cannot tune a bleed threshold. It reads **H2 or the first real session**.

## Scope — keep `models fetch` narrowly VAD-specific · **accepted**

The reviewer accepts the activity command, the composed report, and the VAD half of
`models fetch` as reasonable milestone work, with one caution: do not freeze M6b's
multi-model lock semantics in passing. The lock records only what was fetched, and it is
marked provisional until M6b closes — the same treatment M0 gave the transcript schema
version.

## Ordering

The reviewer's recommended sequence is adopted: fixture union and OQ-017 first, then the
Silero wording amendment, then the fully specified graph contract, then the detector
lifecycle and its partition-invariance proofs, then the split cache identities, then the
conservative-overlap fixture, and only then the DSP — with the runner's failure and report
envelope designed before any of it.
