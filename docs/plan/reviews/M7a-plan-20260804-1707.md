# M7a independent plan review — 2026-08-04 17:07

**Reviewer:** independent Codex CLI, read-only plan review
**Disposition:** nine findings accepted; charter rewritten before implementation

The reviewer would not approve the first M7a draft. The overall private-archive direction was
sound, but four P0 findings could have broken an invariant or produced an incomplete restore.
All findings below were accepted. No code had been written.

## Findings and disposition

1. **P0 — archive settings would invalidate processing caches.** Adding an `archive:` section
   to `SessionConfig` would change the global config hash, processing schema version, every
   stage projection, and transcript-record compatibility. **Accepted.** M7a now requires a
   separate environment/operator-profile `ArchiveRuntimeConfig`, no processing schema bump,
   and regression tests freezing every existing artifact/cache identity.

2. **P0 — the proposed source set was internally inconsistent.** The INV-01 snapshot includes
   every regular file under configured source roots; inspection records audio candidates and
   may leave entries unassigned. A mandatory track-based key could neither represent nested
   notes nor preserve unassigned identity. **Accepted.** The charter now defines one hardened
   `ArchiveSourceSet` with exact relative paths and optional track IDs. Whole-session operations
   cover every entry; track operations select only genuinely attributed entries.

3. **P0 — bounded memory did not satisfy INV-07's disk requirement.** One staged file can still
   exhaust disk, and a corrupt zstd frame could expand past its declared original size before a
   final hash failure. **Accepted.** Worst-case disk preflight, one-object staging, decoded-size
   ceilings, ENOSPC cleanup, and a composed reader-through-writer bounded-resource proof are
   explicit gate criteria.

4. **P0 — the existing snapshot traversal follows symlinks.** Reusing it for upload could send
   a file outside the approved source root under an innocent key. **Accepted.** Upload-side
   `lstat`, every-component symlink refusal, resolved-root containment, and independent restore
   path tests are required; the existing helper is not blindly reused.

5. **P1 — disaster recovery still appeared to require the lost session directory.**
   **Accepted.** Only `upload` and local comparison take a directory. `list`, `verify`, and
   `restore` work from remote session ID plus archive runtime configuration. The one remote
   manifest contains standalone decode/path instructions.

6. **P1 — encoding and fixed-manifest identity were underdefined.** A zstd upgrade could create
   different bytes at the same key, and HEAD-then-PUT is not a concurrency primitive.
   **Accepted.** Archive v1 freezes byte-stable encoder behavior, versions its prefix, tests
   compressed bytes, enforces a single writer, and treats a full canonical existing-manifest
   match as idempotent success and any difference as fatal.

7. **P1 — “no deletion authority” overstated DigitalOcean permissions.** Multipart abort and
   object deletion share a provider permission bundle even if the application never deletes a
   completed object. **Accepted.** The charter distinguishes broad upload credentials from the
   application's abort-only surface, forbids `DeleteObject`, and supports separate read-only
   credentials for discovery, verification, and restore.

8. **P1 — cheap status could misleadingly say `verified`; multipart was only optional.**
   **Accepted.** Status reports `committed` or `previously_verified_at_commit`; only a current
   full GET/decompression says `verified`. A separate mandatory archive-operation report carries
   partial/failure semantics. Multipart is required above the provider's single-PUT limit, with
   minimum-part, persisted-upload-ID, abort, retry, and boundary tests.

9. **P2 — uploading the four real samples was unnecessary provider-smoke scope.** **Accepted.**
   The real files remain local evidence for zstd. Provider smoke and remote-only restore use
   generated bytes, including a forced multipart path.

## Additional owner input incorporated

DigitalOcean Cold Storage bills objects below 128 KiB as 128 KiB. The revised design uploads
exactly one small control object per session: the deterministic committed manifest. It uploads
no per-file JSON sidecars, receipts, FFprobe dumps, or reports; bounded metadata and standalone
restore instructions are consolidated into that manifest. Source audio remains one immutable
compressed object per source path for partial retry and track restore ergonomics.

## Result

The revised plan now starts with source-set, path, configuration, resource, report, permission,
and remote-only recovery contracts before it chooses an SDK or writes provider code. The raw
review transcript remains ignored because it includes local operator notes.
