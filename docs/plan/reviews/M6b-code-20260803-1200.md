# M6b code review — Codex, 2026-08-03

Independent review of the implementation on `milestone/M6b-qwen-adapter`, run in the verify
phase before close (`./scripts/codex-review.sh code 6b`). Distilled from the raw transcript,
which is gitignored because a reviewer quotes every file it read.

**Verdict:** *"I would not close M6b in its current state."*

Eight findings. **Six accepted and fixed, two rejected with reasons**, both rejections
recorded below rather than dropped. Four of the accepted six are defects a passing gate,
a green host-smoke run and a clean self-review had all missed — they are the reason this
step is not optional.

A second, independent reviewer ran in parallel with no knowledge of this one and reached
finding 6 by a different route, plus two minor items recorded at the end. The overlap is
worth noting: the one finding both independent readers produced unprompted is the one about
an invariant asserted in prose and nowhere in a test.

---

## Accepted

**1 — `install_snapshot` returned before recording the lock.** For an already-verifying
tree the early return skipped the lock write, so deleting `models.lock.json` and re-running
`models fetch --qwen` reported a lock path it had not written and left the snapshots section
missing. `fetch` has repaired a deleted lock without re-downloading since M3 and the
snapshot half silently did not, for a six-gigabyte download whose whole justification is
being cheap to re-run as an "am I set up?" check.
*Fixed:* the early return reconstructs the entry from the manifest first.
*Test:* `test_it_repairs_a_deleted_lock_without_downloading`, which asserts no download
happened as well as that the lock came back.

**2 — A configured revision could be set but never installed.** `session.yaml` accepted
`asr.model_revision`, `_default_transcriber` required a snapshot at exactly that commit, and
`models fetch --qwen` always installed the revision pinned in the build and took no
argument. So the completion gate's *"explicit model/aligner revisions may be set in
configuration"* was satisfiable in configuration and unreachable in practice: `process`
would report "revision not installed" forever with no permitted command able to fix it.
Tests covered `install_snapshot(..., revision=...)` — the internal function — and never the
operator's route to it.
*Fixed:* `--asr-revision` / `--aligner-revision` on both `models fetch` and `models plan`,
validated to the same commit shape `AsrConfig` enforces.
*Tests:* `test_a_configured_revision_can_actually_be_installed`,
`test_fetch_takes_the_same_overrides_plan_does`,
`test_a_revision_that_is_not_a_commit_is_refused_at_the_command_line`.

**3 — Configured model identifiers were ignored and recorded as used.**
`_default_transcriber` always loaded the `QWEN3_ASR` and `QWEN3_ALIGNER` descriptors while
the bundle recorded `config.asr.model` verbatim. A session naming any other repository would
run Qwen and write that other name into the ASR cache key *and* the ingest report — two
artifacts asserting that weights which were never loaded produced the transcript, with
nothing downstream able to detect it (INV-08).
*Fixed:* refused at configuration load. These fields exist because the spec's `session.yaml`
has them; this build carries snapshots for exactly two repositories and no command can
install a third, so the honest answer to a third is a refusal naming `model_revision` as the
thing that *is* adjustable.
*Tests:* `test_a_repository_this_build_has_no_snapshot_for_is_rejected`,
`test_the_aligner_is_guarded_the_same_way`.

**4 — `process --fake-models` could silently mix with the real detector.** The hole opened
when this milestone taught `_resolve_or_defer` to turn a model failure into the transcript
branch's error so the mix survives it (INV-09) — right for a host with no ASR weights, wrong
under `--fake-models`, where the same call builds *both* seams from `fake-models.json`. A
missing or malformed file was caught, the run continued with no models and the caller's
`detector` — `None` from the CLI — and activity therefore built the **real** Silero
detector. An operator who explicitly asked for fake models would have received a real MP3
and a real activity graph off real detection, with only a failed transcript stage as a hint,
on any host where the VAD model is installed. `transcribe` had refused this since M4; the
adjacent comment claimed `process` did too.
*Fixed:* `--fake-models` is never softened.
*Test:* `test_a_missing_fake_models_file_never_falls_back_to_the_real_detector`.

**5 — Smoke measurements did not establish what the ledger recorded from them.** Two parts
accepted, one narrowed, one rejected (below).

- *Timestamp stability had a selection bias.* Pairing on "same key **and** overlapping" is
  how M4's stitch rule pairs, but using it to *measure* the rule excludes its own failures:
  a word whose two placements drifted far enough to stop overlapping leaves the sample
  entirely. "20 paired, worst 0 ms" was true and would have been equally true of a model
  that got half of them badly wrong. *Fixed:* an independent denominator — every word of the
  shared span whose text appears in both — and a ratio assertion beside the delta one.
  Re-measured across all four recordings, the real answer is **77 of 80 paired**, not 100%;
  OQ-018(2) is corrected, including a note on which of the three misses are the
  measurement's fault and which is real. A first draft of the new delta bound was also
  wrong at 250 ms and passed only because TX01 sorts ahead of TX03, whose worst is 400 ms.
- *The padding test's name claimed a result its assertions did not check* — and the measured
  result is the opposite of the name, since both texts came back identical. *Fixed:* renamed
  to describe the instrument. The finding itself was already recorded correctly under
  OQ-018(1).

**6 — The report-provenance criterion had no proof.** The charter named
`test_report_records_the_whole_asr_stack` and it did not exist. What existed covered the
pieces and not the wiring: `ReportBuilder` tested with a hand-made `RuntimeProvenance`,
`TranscriberIdentity` tested as a model, and the one end-to-end provenance test running a
*scripted* transcriber whose bundle leaves every one of these fields `None` — so every
conditional branch in `_record_transcriber` was unexecuted and `record_runtime` was never
called by a run at all. **Both reviewers found this independently.**
*Fixed:* written, carrying a fully-populated real-shaped bundle through the production path
and asserting each name the spec lists, in the report and in the records.

**7 — The raw artifact conflated "the aligner raised" with "the aligner was never asked".**
Both recorded `calls: ["transcribe"]`. `public_document` is the per-segment audit artifact an
operator consults exactly when a transcript looks wrong, and the transcript itself reports
only one `alignment_failed` note per *track*, so this was the only place an individual
failure could have survived. The test asserting the behaviour had a docstring describing the
opposite — it stated the property and then pinned its violation.
*Fixed:* three outcomes, three documents; the failure carries the exception's type and
message. *Tests:* `test_it_records_which_calls_were_made` rewritten, plus
`test_the_three_alignment_outcomes_are_all_distinguishable`, which asserts the property
rather than three literal call lists.

**8 — ADR-0028 and the charter still declared `end <= start` malformed.** The code was
amended by the first real transcription — the aligner quantizes to 80 ms, so a shorter word
comes back zero-length, and treating that as corruption discarded every word time in the
segment — but the durable documents were not. An ADR is what the next implementor trusts,
and following this one would have reintroduced the loss. The same ADR also claimed the
low-energy split question was answered, contradicting OPEN-QUESTIONS.
*Fixed:* both amended, with the measurement and the reason the earlier rule was wrong.

## Rejected

**1 (first half) — "the default revision must require a lock entry."** The reviewer is right
that the criterion's literal text says `process` uses the lock, and right that
`snapshot_manifest` trusts the checked-in manifest for the pinned revision without consulting
one. Rejected because ADR-0027 made that asymmetry deliberately and it is **strictly
stronger**, not weaker: the pinned manifest is in version control, was reviewed, and cannot
change on a host without showing in `git diff`, whereas the lock is a JSON file any process
can edit and is *derived from* the manifest. Requiring it would make a correct, fully
verified installation unusable because a cache file was deleted, and would protect nothing —
the criterion exists to prevent re-resolving a moving branch, which a checked-in commit
prevents absolutely. The lock remains authoritative for an *overridden* revision, where it is
genuinely the only manifest that exists. What was wrong was the charter's proof table naming
a test for the opposite rule; that has been corrected rather than the code.

**5 (in part) — "the promised OQ-009 >180 s waveform experiment is absent."** Correct that no
such test exists. Rejected because submitting a >180 s waveform would exercise a path this
pipeline cannot take: `asr.max_segment_s` is capped at 120 by configuration, and the chunking
limit is reached only through `transcribe(return_time_stamps=True)`, which the adapter never
calls — it makes the two public calls separately. A test would have to construct a request
the planner cannot produce and call a method the adapter does not use, and would then be
pinning upstream's behaviour rather than this project's. OQ-009 is answered from the
package's own source, which is where the number lives.
`test_the_chunking_limit_is_reached_only_through_a_call_this_project_never_makes` asserts
exactly that, and its name is the claim.

*Also noted, not a defect:* that no test measures whether a low-energy split resolves
truncation. True, and OPEN-QUESTIONS says so with the reason — 47 seconds of one person
testing microphones cannot exhaust a 1024-token ceiling. Recording an unmeasured thing as
unmeasured is the correct outcome; ADR-0028 claiming otherwise was finding 8, and is fixed.

## From the second reviewer

Beyond finding 6, two minor items, both accepted:

- `doctor`'s docstring still said "The ASR models arrive with M6b." *Fixed.*
- `AsrConfig._check_revision` used `re.match` where `$` also matches before a trailing
  newline, so a YAML block scalar could carry a 41-character "commit" into a directory name.
  *Fixed:* `re.fullmatch`, with `test_a_revision_with_a_trailing_newline_is_rejected`.

That reviewer explicitly checked for and found **no** circular fixtures, weakened
assertions, placeholders, unexplained skips, or INV-04 violations, having verified the
timestamp decoder against the installed aligner's own rounding behaviour rather than against
this project's description of it.
